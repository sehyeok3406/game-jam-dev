### v0.10.1 홈 프로젝트 정리

[v0.10.1 설치판](https://github.com/sehyeok3406/game-jam-dev/releases/tag/v0.10.1)을 정식 게시했습니다. v0.9.2/v0.10.0 업데이트 피드와 공개 다운로드·파일 해시를 검증했습니다.

홈 우측에서 전체·로컬·공동 유형을 필터하고, 이름·생성일·마지막 수정일·최근 열기 기준으로 순서를 바꿀 수 있습니다. 썸네일/목록 보기와 정렬·필터 선택은 이 PC에 기억합니다. 폴더 분류·검색과 함께 적용되며 프로젝트 파일을 바꾸지 않습니다.

홈의 프로젝트 우클릭 또는 `…` 메뉴에서 열기·실제 이름 변경·폴더 이동·로컬 저장 위치 보기/공동 서버 주소 변경을 제공합니다. 로컬 이름은 `project.md`의 `project_name`과 제목에 저장하며, 공동 이름은 관리자가 온라인에서 서버 이름을 변경해 팀원에게 반영합니다. 저장 경로·프로젝트 ID·세션은 유지합니다. 사이드바 `폴더 +`는 이 PC만의 분류 기능이며 실제 파일을 이동하지 않습니다. 폴더를 삭제해도 프로젝트는 전체 목록에 남습니다. 로컬 원본과 공동 서버 사본은 계속 별개이며 역동기화하지 않습니다. **공동 이름 변경·생성일·수정일 제공에는 v0.10.1 협업 서버 코드도 필요합니다.** [릴리스 노트](RELEASE_NOTES.md), [업데이트 안내](UPDATES.md)

- Figma UI3 방식의 하단 플로팅 도구막대: 선택, 이동, 메모, 새 파일, 섹션 (AI 동작은 상단으로 통일)
- 선택한 Markdown 파일을 실제 멤버십으로 묶는 Figma식 섹션
- 파일을 섹션 안팎으로 드롭할 때 추가·제외·이동 여부를 확인한 뒤 반영
- 섹션 우클릭으로 파일을 유지한 채 묶음을 해제하거나, 경고 후 섹션과 멤버 파일을 함께 휴지통으로 이동
- 섹션을 선택하면 섹션 파일과 모든 멤버 문서를 하나의 AI 작업 범위로 전달
- `Shift+클릭` 다중 선택과 `Ctrl+A`, `Ctrl+C`, `Ctrl+V`, `Esc` 캔버스 단축키
- 선택한 카드의 네 변과 모서리를 Windows 창처럼 드래그해 크기 조절
- 빈 캔버스 우클릭으로 새 메모와 AI 작업을 만드는 컨텍스트 메뉴
- 화면을 차지하지 않는 플로팅 상단 메뉴와 숨김/복원 버튼
- 정리 문서가 참고한 여러 원본 메모를 `sources`로 표시
- 선택 문서 기반의 AI 정리/HTML 구현 작업 요청 파일 생성
- 데스크톱에 설치된 GPT·Claude·Gemini CLI 연결 상태 탐지
- 선택한 개인 AI로 실행하고 진행 로그·완료·실패·취소 상태 표시
- AI 실행 팝업에서 제공자와 모델 버전을 선택하고 작업별 설정으로 전달
- 실행 중인 AI 작업을 즉시 중지하고 하위 프로세스까지 종료
- 진행 로그를 직접 스크롤하거나 새 로그가 추가될 때 자동으로 최신 위치 추적
- AI 작업 패널을 상태와 중지 버튼만 남는 상단 바로 최소화·복원
- 이미 생성된 AI 작업 카드에서 작업 지시 복사 가능 (실행 팝업에서는 복사 전용 생성 기능 제거)
- 새 HTML은 `output/games/v1-게임이름/index.html`, `v2-게임이름/index.html`처럼 전용 폴더에 저장하고 각각 샌드박스된 미리보기 창으로 표시 (이름 미입력 시 `v1/index.html`)
- 결과 폴더에는 실행 HTML만 저장하며 CSS·JavaScript·선택한 이미지는 HTML 안에 포함. AI 지시·기획 문서·히스토리·캔버스 정보는 별도로 관리하므로 결과 폴더만 복사해서 보관·전달 가능. 게임 엔진용 프로젝트로 자동 변환하는 기능은 아님
- HTML 창의 제목 바·테두리 우클릭 → ‘파일 탐색기에서 열기’로 해당 HTML을 선택. 협업 중에는 현재 PC의 최신 서버 사본 폴더를 열며 원본 로컬 프로젝트는 변경하지 않음
- 기존 `output/index.html`, `output/versions/*.html`, 불러온 HTML의 경로는 유지하며 업데이트·히스토리·독립적인 창 상태와 호환. 협업에서는 참여자 앱과 서버 모두 v0.8.1 이상으로 업데이트 필요 (새 폴더 경로는 구형 앱에서 지원하지 않음; 서버 번들 업데이트 후 재시작)
- HTML 구현 시 기존 결과가 있으면 ‘기존 결과 업데이트’/‘새 버전 만들기’를 선택하고, 여러 결과 중 기준 버전을 지정
- 기존 결과 업데이트는 지정 파일만 갱신하고 이전 내용은 히스토리에 보관; 새 버전은 기준 HTML을 참고하되 기존 결과는 변경하지 않고 검증 성공 후 별도 창 추가
- HTML 창마다 버전 번호, 독립적인 위치·크기·화면 비율·최소화 상태·히스토리·전체화면 플레이 지원
- HTML 실행 창의 이동·크기·최소화 상태를 프로젝트별로 저장하고, 최소화 시 게임을 유지하며 다시 실행 버튼 제공
- HTML 창 전용 화면 설정: 모바일 세로/가로·태블릿·PC·정사각형·울트라와이드 해상도와 정확한 비율 표시, 고정 크기 선택 시 크기 조절 잠금, 자유 비율 복귀 시 기존 크기 복원
- HTML 창 상단의 화면 설정 버튼으로 비율 팝업을 열고, 전체화면 플레이 버튼으로 같은 게임을 확대하여 플레이 (`Esc`/종료 버튼으로 복귀, 고정 비율·해상도 유지, 자유 비율은 전체 영역 사용)
- AI 실행 전 관련 문서의 편집 저장을 기다리고, 준비·실행·검증 동안 관련 입력·이미지·결과만 보호. 새 문서와 무관한 기존 문서는 계속 편집 가능
- 입력과 기존 결과를 별도 작업 폴더에 복사하여 실행하고, 실패·중지 시 기존 결과 유지
- 결과 파일 갱신·Markdown 필수 정보·출처와 HTML 초기 실행 오류를 검증한 후 반영
- 프로젝트·문서·HTML 히스토리에서 변경 전후 확인과 개별/묶음 복원, 삭제 문서 복원 지원
- 앱 종료로 중단된 작업을 다음 실행 시 확인하고, 반영 도중 중단된 결과는 외부 변경이 없으면 자동 복구
- 프로젝트 폴더의 파일 변경을 감지해 화면 자동 갱신
- 프로젝트 폴더 바깥 접근 및 심볼릭 링크 우회 차단

AI 버튼을 누르면 지시와 설정을 편집한 뒤 `AI 실행`을 누릅니다. `.ai/tasks/*.md` 내부 명세를 자동 저장하고 이 PC의 선택 CLI로 실행합니다. 명세 복사 전용 생성 기능은 제거했습니다. 개인 로그인은 공유하지 않으며 계정의 이용 조건·사용량이 적용됩니다. [연결 안내](AI_CONNECTION.md)

문서 정리·HTML 구현 팝업의 **작업 지시**에는 해당 작업의 기본 지시문이 미리 채워집니다. 그대로 실행하거나 수정·추가할 수 있으며, `기본값으로 복원`으로 되돌립니다. 입력한 내용이 기본 지시문을 대체해 작업 요청 Markdown에 저장되고 CLI에 전달됩니다. 지시는 작업별로 적용되며 다음 새 요청은 다시 기본값으로 시작합니다. 최대 20,000자이고 빈 내용으로 실행할 수 없습니다. 입력 파일 보호, 선택 범위, 지정 출력 경로, 새 버전/업데이트 규칙과 관리자 권한은 편집할 수 없는 보호 규칙입니다. 협업에서는 서버도 v0.7.5 이상이어야 하며 구버전 서버가 지시를 누락시키지 않도록 실행을 차단하고 업데이트 안내를 표시합니다.

현재 자동 실행 정책은 다음과 같습니다.

- 작업 디렉터리는 프로젝트의 `.history/<작업 ID>/workspace`로 고정하고 입력은 `input` 폴더에 별도 보관
- 사용자 전역 Codex 설정은 실행에서 제외해 등록된 MCP를 불필요하게 시작하지 않음
- 작업 명세의 `expected_outputs`에 지정된 결과만 원본 프로젝트에 반영
- 결과 반영 전 작업 폴더의 입력 변경과 원본 프로젝트의 외부 변경을 확인하고, 충돌 시 반영 보류
- 결과 검증 후 자동 적용하며, 중지·실패한 작업의 미완성 파일은 원본에 적용하지 않음
- 작업 상태와 최종 결과를 요청 파일의 frontmatter에 기록
- 모델 선택은 해당 작업에만 `--model`로 적용하고, 자동 선택은 선택 CLI의 기본 모델을 사용

현재는 아이디어 → 문서 정리 → HTML 구현 흐름과 초기 서버 협업을 검증하는 데스크톱 프로토타입입니다. 문서 정리 방식은 기존 수준을 유지하며, 웹 클라이언트·계정·결제·서비스 제공자의 AI API 실행은 이후 단계입니다. 기존 로컬 모드는 그대로 사용할 수 있습니다.

히스토리는 `.history/`에 Markdown/HTML 원문과 기록 메타데이터를 보관합니다. HTML 창 배치는 문서가 아닌 앱 메타데이터로 기본 결과는 `.canvas/preview.json`, 추가 버전은 `.canvas/previews/v2.json` 등에 저장합니다. 문서·섹션 배치는 드래그/크기 변경 완료 시 기록하고 실행 취소를 지원하며, HTML 창 배치는 문서 편집 히스토리에 포함하지 않습니다. 복원도 새 기록으로 남기므로 복원 직전 상태를 다시 확인할 수 있습니다. 섹션 관계가 바뀐 기록은 관련 파일을 함께 복원합니다. 버전 번호는 작업 요청에서 예약하므로 취소·실패한 번호를 다시 사용하지 않으며, 완료된 새 버전 생성 요청을 재실행해 기존 결과를 덮어쓰는 것도 막습니다.

HTML 검증은 제한된 별도 실행 창에서 초기 로드와 약 1초 동안의 문법·실행·Promise 오류를 확인합니다. 이후 플레이 중 발생하는 오류나 게임 규칙의 정확성까지 보장하는 검사는 아닙니다.

## 실행

```powershell
npm install
npm start
```

검증 명령:

```powershell
npm run typecheck
npm run lint
npm test
npm run test:integration
```

통합 검증은 임시 프로젝트와 가짜 CLI로 실행·중지·충돌·복원 흐름을 확인하며, HTML 실행 검증은 실제 Electron을 사용합니다. 개인 AI 사용량이나 기존 프로젝트 파일을 사용하지 않습니다.

Windows용 앱 폴더를 만들려면 다음을 실행합니다.

```powershell
npm run package
```

결과는 `out/`에 생성됩니다.

## 프로젝트 폴더 구조

아래 파일/휴지통/로컬 히스토리 설명은 기존 로컬 모드 기준입니다. 공동 프로젝트는 서버 체크포인트와 서버 히스토리를 사용합니다. 관리자는 히스토리에서 복원할 수 있으며 편집자는 현재 세션의 본인 삭제/편집 작업을 실행 취소할 수 있습니다. 자세한 차이는 [협업 사용 안내](COLLABORATION.md)를 참고하세요.

빈 폴더를 선택해도 앱이 필요한 구조를 자동으로 만듭니다.

```text
my-game/
├─ project.md
├─ ideas/
│  └─ idea-xxxx.md
├─ docs/
│  ├─ game-overview.md
│  ├─ core-loop.md
│  └─ imported/
│     └─ import-xxxx.md
├─ assets/
│  └─ images/
│     └─ import-xxxx.png
├─ sections/
│  ├─ player-character.md
│  └─ monster-character.md
├─ .ai/
│  └─ tasks/
│     └─ organize-xxxx.md
└─ output/
   └─ index.html
```

## Markdown 메타데이터

각 문서의 YAML frontmatter가 캔버스 위치와 출처를 저장합니다.

```md
---
id: core-loop
title: 핵심 게임 루프
type: system
status: draft
x: 900
y: 120
width: 380
height: 420
collapsed: false
sources:
  - id: idea-night-farm
    path: ideas/night-farm.md
    contribution: 낮과 밤의 역할 구분
  - id: idea-automation
    path: ideas/automation.md
    contribution: 자동화 장치 아이디어
---

# 핵심 게임 루프
```

`type`은 `idea`, `system`, `overview`, `question`, `ai-task`, `reference`(외부 참고 MD), `image`(이미지 설명 문서) 중 하나를 사용합니다.

`collapsed`는 카드의 최소화 상태입니다. `true`이면 제목이 포함된 상단 바만 표시되며 원래 `height`는 펼칠 때 복원할 수 있도록 유지됩니다. 문서 카드의 우클릭 메뉴에서 삭제하면 실제 Markdown 파일은 Windows 휴지통으로 이동하고, 해당 문서가 속한 섹션의 `members`에서도 자동으로 제거됩니다. `project.md`도 삭제할 수 있으며 프로젝트를 다시 열어도 자동으로 생성하지 않습니다. 프로젝트 초기화 여부와 이름은 `.canvas/project.json`에 별도로 보관합니다.

HTML 결과도 우클릭 메뉴나 다중 선택 후 Delete 키로 삭제할 수 있습니다. `output/games/vN-이름/` 형식의 전용 결과 폴더는 내부 파일·하위 폴더까지 통째로 휴지통으로 이동하고, 해당 결과의 창 설정과 HTML 원본 관리 문서도 함께 삭제합니다. 기존 `output/index.html`, `output/versions/*.html`, 불러온 HTML은 부모 폴더를 다른 결과와 공유하므로 해당 HTML과 관리 정보만 삭제합니다. 결과 생성에 사용한 원본 메모·기획 문서와 다른 결과물은 유지합니다.

## 섹션 파일과 멤버십

섹션은 화면 장식이 아니라 `sections/*.md`에 저장되는 실제 작업 단위입니다. 한 문서는 동시에 한 섹션에만 속하며, 새 섹션으로 옮기면 이전 섹션의 멤버 목록에서 자동으로 빠집니다.

```md
---
id: section-player-character
title: 플레이어 캐릭터
type: section
status: active
x: 40
y: 60
width: 860
height: 620
members:
  - id: player-visual
    path: ideas/player-visual.md
  - id: player-skill
    path: docs/player-skill.md
---

# 플레이어 캐릭터
```

멤버는 안정적인 `id`와 사람이 확인할 수 있는 `path`를 함께 저장합니다. 파일 경로가 바뀌어도 동일한 ID를 찾으면 경로를 복구합니다. 섹션을 이동하면 내부 문서들의 `x`, `y` 좌표도 함께 갱신됩니다. 섹션을 선택하고 AI 정리 또는 HTML 구현을 누르면 섹션 Markdown과 모든 멤버 Markdown이 입력으로 포함됩니다. 섹션 이름이나 멤버십을 직접 관리하려면 섹션 헤더의 폴더 버튼으로 해당 Markdown 파일을 열 수 있습니다.

파일 카드의 중심점을 섹션 안으로 드롭하면 해당 섹션에 추가할지 확인합니다. 섹션 밖으로 드롭하면 제외 여부를, 다른 섹션으로 드롭하면 기존 섹션에서 제외하고 새 섹션에 추가할지를 한 번에 확인합니다. 취소하면 파일은 원래 위치와 소속으로 돌아가며, 확인한 경우에만 문서 좌표와 `sections/*.md`의 `members`가 함께 갱신됩니다.

섹션 우클릭 메뉴의 `섹션 해제`는 섹션 Markdown만 휴지통으로 보내고 멤버 파일은 섹션 없는 상태로 유지합니다. `섹션과 파일 삭제`는 별도 경고창을 거친 뒤 섹션과 멤버 파일을 모두 Windows 휴지통으로 이동합니다. `project.md`도 섹션 멤버이면 함께 삭제합니다.

## 캔버스 단축키

- `Ctrl+I`: 외부 Markdown·이미지 파일 불러오기
- `Shift+클릭`: 메모·파일 다중 선택 또는 선택 해제
- `Ctrl+A`: 캔버스의 모든 Markdown 파일 선택
- `Ctrl+C`: 선택 파일을 앱 내부 클립보드에 복사
- `Ctrl+V`: 새 ID와 새 `.md` 파일을 만들어 오른쪽 아래에 붙여넣기
- `Esc`: 메뉴와 대화상자를 닫고 선택 해제
- `V`, `H`, `N`: 선택, 이동, 메모 도구 전환

복사본은 원본 파일과 독립적이며 섹션에는 자동으로 포함되지 않습니다. 입력창이나 Markdown 편집기 안에서는 Windows의 기본 텍스트 단축키가 우선합니다.

## HTML 전체화면 마우스 조작 (0.7.8)

HTML 결과 창의 전체화면 버튼을 누른 뒤 게임 화면을 클릭하면, 게임에서 구현한
마우스 캡처(Pointer Lock)를 사용할 수 있습니다. 일반 캔버스에서는 캡처를 허용하지
않으므로 기존 게임의 드래그 조작을 사용합니다. 전체화면 종료 시 커서를 해제하며,
전체화면 전환만으로 게임을 다시 로드하지 않습니다. `Esc`로 마우스 캡처를 풀 수 있습니다.
게임 자체가 포커스를 잃으면 일시정지하도록 구현되어 있다면, 전체화면 진입 후 게임의
재개 버튼이나 안내에 따라 다시 시작하세요. 원본 HTML 수정이나 AI 재생성은 필요하지 않습니다.

전체화면 허용은 앱 UI에만, 마우스 캡처는 전체화면 중인 해당 앱의 `about:srcdoc`
미리보기 프레임에만 허용합니다. 다른 권한은 차단하며, 히스토리 미리보기는 캡처를 허용하지 않습니다.

## 초기 사용 흐름

1. 앱에서 게임별 로컬 폴더를 연다.
2. `+ 아이디어`로 메모를 만들고 카드 내용을 편집한다.
3. 관련 카드 또는 섹션을 선택하고 `gamejam!`을 누른다 (`Ctrl+Enter`).
4. 문서 정리 / HTML 구현을 각각 또는 함께 선택하고, 이름·단계별 지시·새 버전/업데이트 방식·모델을 설정한다.
5. `gamejam! 실행`을 누르면 명세를 자동 저장하고 실행한다. 둘 다 선택하면 문서 정리를 먼저 검증한 뒤 그 문서와 선택 이미지로 HTML을 구현한다.
6. 실행 패널에서 진행 로그를 확인한다. 연속 실행은 두 단계 내내 편집 잠금을 유지하고, 모든 검증에 성공한 문서·HTML을 한 번에 반영한다. 실패·중지하면 기존 결과를 유지한다.
7. HTML 결과 창에서 플레이하거나 전체화면으로 테스트한다. 구현만 다시 할 때는 정리 문서를 선택하고 HTML 구현만 체크하면 된다.
