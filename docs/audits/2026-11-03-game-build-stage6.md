# 게임 제작 6단계: HTML 입출력과 상태 안내

2026-11-03. [1차 계획](../plans/2026-11-01-game-build-phase1.md)의 **6단계를 완료**했다. HTML 파일 하나 내보내기·원본을 보존한 재가져오기/새 수정·제작 상태 안내를 구현하고 로컬/공동 프로젝트에서 확인했다. 공개 배포와 7단계 실제 AI 계정·장르별 품질 종합 검증은 이 작업에 포함하지 않는다.

## 사용자에게 달라지는 동작

| 기능             | 동작                                                                                                                        |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------- |
| HTML 내보내기    | 게임 카드의 다운로드 버튼에서 저장 위치를 선택한다. 현재 프로젝트에 저장된 HTML 파일 하나를 그대로 저장한다.                |
| 다시 가져오기    | 기존 파일 가져오기·드롭을 사용한다. 새로운 게임 자료로 등록하고 가져온 원본 HTML을 유지한다.                                |
| 다시 수정하기    | 가져온 HTML을 참고 자료로 선택해 새 게임으로 만든다. AI가 새 수정용 소스를 작성하고 앱이 새 HTML을 빌드한다.                |
| 수정용 원본 안내 | 소스가 보관된 게임, HTML만 있는 게임, 원본 정합성 확인이 필요한 게임을 구분한다.                                            |
| 기준 문서 안내   | 사용한 문서와 라이브러리 버전, 제작 후 내용 변경·삭제·다른 문서 대체·비교 정보 부족을 표시한다. 문서 링크로 편집할 수 있다. |

내보낸 HTML만으로 원래 프로젝트의 소스 구조·기획 문서·수정 이력을 복구하지 않는다. 계속 이어서 수정하려면 원래 프로젝트도 보관해야 한다. 가져온 HTML의 숨은 제작 정보만으로 기존 게임 identity를 연결하거나 라이브러리를 설치하지 않는다.

## 구현과 복구 경계

- `PreviewExportService`가 시작 프로젝트의 저장된 HTML을 읽고, OS 창 뒤와 교체 직전에 세션·현재 파일을 다시 확인한다. 취소는 false이며 저장 성공과 구분한다. UI도 경로/내용 변경·unmount 뒤 늦은 결과를 무시한다.
- desktop은 창에 연결된 OS 저장 창, filesystem adapter는 외부 임시 파일과 원자 교체를 담당한다. 프로젝트 내부와 그곳을 가리키는 junction·일반 파일이 아닌 대상을 거절한다. 기존 저장 큐·히스토리를 우회해 프로젝트를 덮어쓰지 않는다.
- 공유 프로젝트는 현재 읽을 수 있는 공동 snapshot을 사용한다. 기존 접근 거부·삭제·세션 검사를 유지한다. 새 서버 저장 endpoint나 별도 소스 반영 경로는 추가하지 않았다.
- 내보내기는 실행용 srcdoc가 아닌 저장된 HTML이다. 앱 bridge·SDK·debug·task·인증을 새로 삽입하지 않고 기존 라이브러리 고지도 유지한다. 재가져오기는 기존 inert 검사·UTF-8/8MB·scope/context·로컬 저장/공동 명령을 재사용한다.
- 새 manifest의 선택적 `designSha256`은 의미 있는 문서 내용의 baseline이다. 좌표·크기·색·캔버스·갱신 시각·업무 표시 변경은 제외하고 본문·제목·type·ID·출처 등은 비교한다. YAML 순서가 바뀌어도 같게 처리하고 YAML 날짜 값의 의미는 유지한다.
- 예전 전체 hash가 달라졌지만 새 비교 정보가 없으면 unknown이다. 복사에서 문서 ID/path가 바뀐 경우도 비교 hash를 제거해 unknown으로 남긴다. 과거 원본을 재작성하지 않는다. 문서 변화가 게임에 반영됐는지는 자동 평가하지 않는다.
- 안내 영역은 접을 수 있고 최대 180px다. 카드의 나머지는 게임 화면이 사용한다. 실제 화면 확인에서 발견한 불필요한 빈 영역을 수정하고 접기/펼치기·경고·최소화·크기별 높이 검사를 추가했다.
- 실제 Windows 패키지에서 확인한 history rename EPERM에는 기존 내용 확인을 유지한 제한적 재시도를 추가했다. EPERM/EBUSY/EACCES만 최대 5회, 매번 baseline/세션을 검사한다. 대상 삭제 fallback은 없으며 다른 파일 오류와 영구 잠금은 실패로 남긴다.

자세한 책임·계약은 [HTML 입출력 설계](../architecture/game-build-transfer.md), 결정 근거는 [ADR 0005](../architecture/decisions/0005-game-builds-and-standalone-html.md)를 따른다. 아키텍처 예외나 허용 규칙을 추가·완화하지 않았다.

첫 통합 실행에서는 일시적인 ResizeObserver 알림을 오류로 받은 캔버스 검사가 실패했다. 빌드와 UI 재실행을 겹쳤을 때 Vite reload와 메뉴 대기도 발생했다. 빌드가 끝난 뒤 전체 통합을 다시 실행해 기존 오류 검사를 유지한 채 통과했으며, 오류 필터나 타임아웃을 완화하지 않았다. 별도 화면 검사에서 새 안내의 레이아웃 문제를 발견해 flex 배치·고정 header 높이로 수정했다. 행 개수 같은 이전 grid 구현 검사 대신 안내를 제외한 실제 플레이 높이와 iframe 높이의 일치를 검사한다.

전체 포맷 실패 파일은 이번 작업과 무관한 `docs/plans/2026-11-02-shared-location-links.md`다. 기존 별도 작업을 변경하지 않고 남겼다. 이 문제를 제외한 6단계 소스·검사·설계/완료 문서의 포맷은 통과했다.

### Windows 실제 입출력

`tests/game-build-native-export.mjs`는 현재 패키지에서 실제 Windows 저장/취소 창, 외부 파일 바이트 일치와 프로젝트 내부 쓰기 차단을 확인했다. dialog 도우미는 해당 테스트 앱의 PID·소유 dialog·자식 control에만 Win32 메시지를 전달한다. 제품에 테스트용 저장 우회 API를 넣지 않았다.

`GAMEJAM_BUILD_EDITING=1`, `GAMEJAM_BUILD_TRANSFER=1`, `GAMEJAM_PUBLIC_BUILD=1`을 설정한 `tests/game-build-execution-packaged.mjs`는 기존 IPC/CLI 파일 교환·실제 bundler/HTML 검사·로컬/공동 저장에 다음을 추가한다.

1. 실제 게임 카드의 내보내기 버튼과 저장 창을 사용한다. 취소 후 파일 부재, 저장한 바이트의 원본 일치, 원본 상태·문서 상태·정확한 라이브러리 버전 표시를 확인한다.
2. 실제 내보낸 파일을 현재 프로젝트 scope/context로 다시 가져온다. 별도 HTML 자료로 등록되며 기존 source identity를 자동 연결하지 않는다.
3. 가져온 HTML만 자료로 주어 새 source를 제작한다. 내장 이미지를 재사용하고 새 게임을 만들며 가져온 원본을 보존한다. 기존 HTML의 lock을 자동 설치하지 않는다.
4. 기존 source 수정·고정 Three.js lock·새 버전·실패 rollback·문서 갱신·기록 복원·재시작도 함께 확인한다.

AI/CLI의 소스 작성은 로컬 모의 Claude다. 실제 npm Three.js·동봉 도구·Electron 검증·Windows 파일 저장·협업 서버와 구분한다. 모의 CLI 재요청은 이전 coordinator의 자원 정리가 끝나기 전 반환되는 명시적 ‘AI 작업 중’ 사전 거절만 기다리며 중복 실행을 허용하지 않는다.

### 브라우저·화면 증거

내보낸 shared HTML과 재가져와 수정한 HTML을 각각 Windows Chrome·Edge의 file://에서 검사한다. 내장 이미지 decode·목숨 9 표시·키 입력 후 canvas 변경·외부 요청 0건·JavaScript 오류 0건을 확인한다. 픽셀 fixture의 기동·조작 검증이며 아트 품질·장시간 플레이·모든 게임의 호환성 평가가 아니다.

로컬 증거는 `out/game-build-stage6/`의 `package-evidence.json`, `transfer-local.png`, `transfer-shared.png`, `export-*.html`, `reimport-*.html`, `export-browser-evidence.json`, `browser-evidence.json`이다. 화면 배치 검사는 `out/html-preview-ui/`에 결과와 테마·크기별 스크린샷을 남긴다. 이 폴더들은 재생성 가능한 로컬 산출물이며 공개 업로드하지 않았다.

## 남은 제약과 다음 단계

- 실제 Codex/Claude/Gemini/Grok 계정은 호출하지 않았다. 네 공급자 공통 준비·수정 계약의 기존 검사와 이번 모의 Claude 패키지 검사를 실제 계정 품질 검증으로 간주하지 않는다.
- HTML은 8MB 한도를 유지한다. 이전 외부 참조 자료를 자동 수집하지 않으며 source/ZIP/폴더 묶음 전송 형식은 추가하지 않았다. 앱의 온라인 멀티 기능은 외부 HTML에서 제공하지 않는다.
- 공개 npm·현재 standalone profile·설치 hook/고지 확보의 기존 제약은 유지한다. 일반 수정에서 라이브러리 추가/제거/업그레이드는 아직 지원하지 않는다.
- 이미지 자동 검색·생성, 자동 요구 충족/비주얼 평가·수정, 모바일, 결제·저장 공간 합산은 후속이다.
- 7단계에서는 실제 공급자 계정, 대표 장르·복합 요구·이미지·비주얼 다양성, 실패/복구와 최종 사용자 흐름을 종합 검증한다. 이번 작업에서 7단계를 시작하거나 배포하지 않았다.
