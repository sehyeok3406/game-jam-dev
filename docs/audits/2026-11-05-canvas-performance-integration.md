# 최신본 캔버스 성능 통합

2026-11-05. v0.44.1의 ec68987을 기준으로 별도 성능 작업의 1~7단계를 통합했다. 브랜치는 codex/integrate-canvas-performance, 내부 패키지 후보는 v0.45.0이다. 커밋·푸시·공개 배포와 사용자의 설치 앱 교체는 아직 수행하지 않았다.

원래 작업 트리는 보존했다. 이전 기준본·성능 변경·최신본을 파일별로 3방향 비교하고 위치/문단 링크의 context·앵커·카메라 intent와 HTML 제작/내보내기 상태를 유지했다. Markdown 캐시 processor에도 앵커 플러그인과 공유 링크 URL 허용을 연결했다. 수동 링크 버튼·입력 패널은 복원하지 않았다.

카메라 상태의 전체 화면 갱신과 전체 JSON 노드 비교를 제거하고 구역 조회·최신 화면 준비·유형별 캐시·편집/IME 보호를 연결했다. 실행 HTML은 iframe을 유지하고 이벤트를 대상별로 라우팅한다. 창 설정의 반복 전체 프로젝트 읽기와 이동 도구의 본문 편집 진입 차단도 포함했다. [책임/수명 안내](../architecture/canvas-performance.md)를 따른다.

## 제한된 검증

타입·core 타입, 아키텍처 10개, 구역/스케줄/캐시/참조/iframe/창 설정 단위 검사 57개와 기존 위치 링크·HTML UI 검사가 통과했다. HTML 미리보기용 proxy가 locationLinks를 함수로 반환해 생기던 기존 오류는 optional namespace를 undefined로 지정해 보완했다. 라이브 서비스나 OS 링크 수신 계약은 변경하지 않았다.

대표 2개 장면을 각각 한 번만 실행했다. 1440×1000 창에서 RAF 간격 P95, 축소 / 확대 순서이며 단위는 ms다.

| 장면         |         P95 | 최대 RAF 간격 |
| ------------ | ----------: | ------------: |
| markdown 300 | 16.8 / 16.7 |          16.8 |
| mixed 300    | 16.8 / 16.8 |          66.6 |

두 장면 모두 카메라 구간의 상위 화면·노드 조립·계측된 비선택 카드 렌더가 0회였고 본문/geometry 쓰기가 없었다. 실제 포인터 pan/wheel과 확대율 변경 중 텍스트 저장 높이도 확인했다. 혼합 장면의 순간 지연은 최대값에 남아 있으므로 모든 프레임·PC에서 60FPS를 보장하지 않는다.

최종 Windows 패키지로 종료/실행 중 링크 수신·실제 OS 전달·문단/텍스트/HTML·크고 작거나 회전한 대상 이동이 통과했다. 최종 app.asar의 성능 표시 class, 게임 제작 summary와 위치 링크/문단 메뉴를 확인했고 수동 링크 class가 없음을 확인했다. 빌드 입력 686개가 패키지 검사 후에도 동일했다. app.asar SHA-256은 4635937d5d72ae80412fdda85d1fa6997b9a033fdf16f0876781c436b86625f8이다.

전체 장면 행렬·장시간 왕복·무관한 전체 테스트는 반복하지 않았다. 카메라 측정 뒤 변경은 디버그 전용 모의 API 한 항목과 서식이며 일반 카메라 구현은 같았다. 원본 모델의 전체 메모리, 한 문서의 동기 처리, 다수 실행 HTML의 비용은 남는다. 새 아키텍처 예외와 계약/권한/저장 정책 변경은 없다.
