# 로컬 복구 초안 2단계 검증

2026-11-22 · Windows x64 로컬 패키지 · 기준 커밋 `54b6567`에 1·2단계 변경 적용

## 초안 저장 정책

Markdown 편집기, 활성 펜·도형, 캔버스 텍스트는 미저장 변경의 최신 상태를 메모리에 유지한다. 첫 변경 30초 뒤부터 상태가 달라진 구간에만 기존 복구 초안 파일을 교체한다. 새 파일 교체가 실패하면 이전 초안을 계속 읽을 수 있다. 원본 저장에 실패했거나 사용자가 작업을 복구용으로 보류하면 즉시 초안을 보관한다. [편집 명령과 저장 경계](../architecture/editing-commands.md#로컬-편집의-복구-초안--2026-11-22)

## 쓰기 횟수

동일한 기준선 입력을 한 번 계측했다. 프로젝트는 일반 Markdown 122개, 섹션 1개, HTML 5개로 구성했고 각 펜 획은 약 0.45초였다. 숫자는 애플리케이션의 파일 쓰기 횟수다. [0단계 측정 조건](2026-11-17-local-save-refresh-baseline.md)

| 시나리오                | 복구 초안 쓰기 · 기준 → 2단계 | 2단계 원본 저장 | 2단계 히스토리 전후 / 항목 쓰기 |
| ----------------------- | ----------------------------: | --------------: | ------------------------------: |
| 메모 입력·자동 저장 1건 |                         1 → 0 |               1 |                           2 / 1 |

세 시나리오에서 전체 문서·섹션·HTML 목록 호출은 각각 0회였다. `out/local-save-baseline/gamejam-resize-packaged-IPFjPS`의 `report.json`과 `trace.json`에 세부 기록과 패키지 지문을 남겼다. 원본·히스토리 쓰기 주기는 3단계에서 다룬다.

## 검증 결과

- Windows 패키지를 첫 펜 초안 쓰기 전과 기록 직후에 각각 강제 종료했다. 첫 기록은 입력 시작 후 약 30.1초에 관측됐다. 재실행에서 기록 직후에 추가한 입력 이전까지의 획을 복구했다. 구형 Markdown·그림 초안을 열었고 버린 그림 초안은 다시 나타나지 않았다. 같은 패키지에서 도형·펜·지우개 Undo/Redo와 외부 Markdown 충돌 보존도 확인했다.
- Windows 패키지에서 원본 이름 확정 전 Markdown 제목과 연속 입력 중인 캔버스 텍스트를 각각 30초 주기에 보관하고 강제 종료 후 복구했다. 캔버스 텍스트 첫 실행에서 그림 충돌 로그가 한 번 나왔다. 다시 실행해 복구 완료 후 원본·초안 제거·화면 오류 없음까지 확인했고 로그도 재현되지 않았다.
- 고정 시계에서 30초 주기, 변경이 없을 때 쓰기 생략, 진행 중 쓰기와 새 입력의 분리, 세션 타이머 취소를 확인했다. 파일 교체 실패를 주입한 검사에서 이전 초안이 남고 다음 교체가 다시 가능한지 확인했다. TypeScript 검사와 `npm test`를 통과했다. 자동 테스트는 1,262개 통과, 선택 검사 1개 건너뜀이며 아키텍처 검사가 포함된다.
- 전체 린트는 기존 미추적 사업 문서의 포맷을 보고했다. 기존 텍스트 검사 중 패키지 스크립트는 종료된 자체 서버 UI를 기다리다 중단됐고 Vite 개발 검사는 테스트 환경의 `node:buffer` 해석에서 중단됐다. 이번 복구 검증은 [Windows 패키지 전용 시나리오](../../tests/local-draft-checkpoint-packaged.mjs)를 사용했다.
