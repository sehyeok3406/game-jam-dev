# 게임 제작 7단계: Codex 실제 제작·공통 기능 검증

2026-11-03. **합의한 Codex 실제 제작·공통 기능 범위의 7단계를 완료**했다. 실제 Codex로 서로 다른 게임 2종과 수정·재가져오기 결과를 만들고 Windows 패키지·Chrome/Edge에서 규칙과 입출력을 확인했다. Claude·Gemini·Grok의 실제 계정·모델 응답·게임 품질 검증은 사용자 합의대로 보류하며 기존 모의 검사 결과와 구분한다. 공개 배포는 하지 않았다.

게임 규칙은 실제 브라우저 키 입력·화면·사용자에게 보이는 HUD로 확인한다. 게임 상태를 테스트 코드로 바꾸거나 미리 작성한 source를 실제 AI 결과로 대체하지 않는다. 제공 PNG는 테스트용으로 코드에서 그린 고양이/숲이며 이미지 자동 검색·생성 기능의 결과가 아니다. 시각적 차이는 스크린샷과 실제 렌더링을 확인하고, 두 표본의 결과를 모든 장르의 재미·균형·아트 품질이나 최소 사양 성능 보증으로 일반화하지 않는다.

`tests/game-build-codex-packaged.mjs`는 `GAMEJAM_REAL_CODEX=1`일 때만 실제 계정을 호출한다. 기본 `npm test`에 포함하지 않는다. `pixel`, `edit`, `neon`, `reimport`, `cancel` 시나리오를 각각 실행하며 기본 인자는 연결 확인용 `probe`다. 현재 앱이 발견한 로그인된 desktop CLI와 앱에 등록된 `gpt-6.1-sol`을 사용한다. 초기 medium 시도 뒤 최종 작은 시나리오에는 low를 사용하며 실제 설정은 history에 기록한다. 개인 설정·인증을 새로 쓰거나 다른 공급자를 구독하지 않는다.

`tests/game-build-codex-browser.mjs <시나리오> [초기 목숨]`는 실제 내보낸 HTML을 Chrome/Edge의 file://에서 검사한다. Canvas 이미지 draw 호출을 관찰하고 웹 요청/오류를 기록한다. Three.js는 실제 WebGL context를 확인하며 브라우저 자동화의 소프트웨어 렌더링 허용 옵션을 최저 사양 인증으로 표현하지 않는다.

## 발견·수정 사항

### 준비 단계에서 요청 파일이 생성되지 않음

첫 실제 Codex 실행은 제작 기준 문서 2개 작성에 성공한 뒤 라이브러리 준비 단계에서 실패했다. 별도 실제 재현에서 Codex가 “셸 없이 사용할 로컬 파일 읽기 도구가 없어 입력을 읽지 못한다”고 응답했다. 준비 prompt의 일괄 `No shell` 지시가 CLI의 기존 파일 I/O까지 막는 원인이었다. 기존 mock executor는 요청 파일을 직접 써서 이 문제를 드러내지 못했다.

수정은 `desktop/ai/dependency-preparation.ts`의 파일 교환 책임에 한정했다. 선택한 입력 경로를 명시하고, 기존 로컬 파일 도구를 사용하며 파일 I/O가 터미널로 제공될 때는 지정 입력 읽기와 요청 JSON 하나 쓰기에만 사용하도록 안내했다. 패키지/프로젝트 코드 실행·설치·외부 요청·추가 도구/권한은 계속 금지한다. CLI 인자·workspace 권한·입력 보존/선언 밖 파일 검사·교환 한도를 완화하지 않았다.

요청 파일이 없으면 임시 경로의 ENOENT만 보여주던 오류도 누락 사실과 제한된 길이의 공급자 마지막 설명으로 바꿨다. 회귀 검사는 이 설명·입력 보존·실패 뒤 stage 정리를 확인한다. 수정 후 별도의 실제 Codex 준비 실행은 `done(null)` 파일 생성에 성공했다. 같은 수정의 Windows 패키지로 전체 제작을 다시 검사한다.

### 작은 게임 창의 화면 맞춤

첫 픽셀 표본은 실행·규칙·PNG 사용을 통과했지만 1100×780 창에서 게임 하단과 조작 안내가 페이지 스크롤 아래로 내려갔다. 소스 작성 단계에 ‘가용 iframe 안에 필수 게임판·HUD·조작을 맞추고 의도하지 않은 페이지 스크롤을 피하라’는 안내를 추가했다. 게임 내부 카메라/월드 스크롤이나 사용자가 명시한 해상도는 금지하지 않는다. 자동 화면 평가/수정 기능을 추가한 것은 아니다.

목숨만 바꾸는 수정 표본은 원래 CSS와 배치를 유지하는 조건을 그대로 검사했다. HTML 재가져오기 표본에서는 기존 이미지·규칙을 유지하면서 화면 맞춤을 요구하고 1100×780·720×520의 실제 게임판·버튼 위치와 문서 overflow를 검사한다. 재가져온 새 게임은 Chrome/Edge 모두 두 창 크기에서 전체 게임판·필수 HUD·조작 버튼이 화면 안에 들어오고 문서 overflow가 없는 것을 확인했다. 원래 표본과 목숨만 수정한 표본의 배치는 보존된다.

## 실행 기록

### 사용량 한도와 상세 오류 보존

첫 소스 작성은 파일 변경까지 진행된 뒤 실제 계정의 사용량 한도로 종료됐다. 별도 공동 프로젝트 실행도 같은 응답을 받았다. 두 실패 모두 기존 문서·이미지·HTML·원본 데이터가 그대로인 것을 확인했으며, 실패한 중간 산출물을 완성된 게임으로 반영하지 않았다. 응답이 안내한 재시도 시각 이후 사용자의 계속 지시에 따라 짧은 실제 호출을 한 번 수행해 `QA_OK` 정상 응답을 확인하고 검증을 재개했다. 제한 중 반복 호출하거나 추가 구독·크레딧 구매를 하지 않았다.

이 과정에서 Codex가 먼저 내보낸 상세 오류가 마지막 `turn.failed`의 일반 문구로 덮이는 문제를 확인했다. Codex adapter는 terminal event의 `error.message`를 읽고 출력 parser는 앞서 받은 상세 실패 사유를 유지한다. UI·history·진단이 기존 경로로 실제 사용량 한도 사유를 전달하도록 했으며, 분할 JSON 수신·상세 오류→일반 종료·단독 terminal 오류·일반 fallback을 회귀 검사한다.

실제 검사 harness도 공동 실행에서는 시작 receipt ID와 history ID가 다를 수 있어 기존 main-flow 검사와 같이 task path로 완료 기록을 찾도록 수정했다. 이미 종료된 작업의 시간 초과 취소 오류가 원래 실패를 덮지 않도록 했다. 제품의 lease·실행 identity 정책을 바꾼 것은 아니다.

- 앱 연결: `codex-cli 0.166.0-alpha.5.1`, ChatGPT 인증 확인. PowerShell PATH의 별도 CLI와 구분하고 앱이 발견한 executable을 사용했다.
- 수정 후 기본 자동 검사: 1,118건 중 1,117 통과, 실패 0, 기존 선택적 Grok CLI 검사 1건 skip. architecture 포함.
- 수정 후 TypeScript 검사: 통과. contracts/core 계약은 이번 단계에서 변경하지 않았다.
- 수정 후 Windows x64 package: 생성 통과. 최종 패키지의 실제 재가져오기/source 제작과 운영 renderer 화면 검사 30개 경우도 통과했다. artifact hash와 실제 receipt는 [측정 JSON](2026-11-03-game-build-stage7-evidence.json)에 기록한다.
- 동봉 runtime의 source/bundle 검사: 6건 통과. 네 공급자 모의 executor의 수정용 사본→실제 bundler 경로 포함. 실제 네 계정 검증을 뜻하지 않는다.
- 동봉 runtime의 준비/registry/cache 검사: 8건 통과. 실제 local registry·압축/무결성·오프라인 lock·고지/API 자료·실패·취소·4개 공급자 모의 교환 포함. 도구 파일은 변경하지 않았다.
- 전체 integration: 통과. 후속 화면 맞춤 prompt는 최종 패키지의 실제 HTML 재가져오기·새 source 제작으로 검사한다.
- 실제 제작·브라우저·화면 검증: 픽셀·수정·3D 퍼즐·HTML 재가져오기 결과 모두 Chrome/Edge에서 통과했다(총 8회). 실제 중단·기존 원본 보존, 재가져오기 창 맞춤도 통과했다. 외부 요청과 JavaScript 오류는 모두 0건이다.
- 린트: oxlint 통과(기존 Discord mock 경고 1건). 이번 변경 포맷은 통과했고 전체 포맷은 수정하지 않은 별도 계획서 `docs/plans/2026-11-02-shared-location-links.md` 한 곳에서 실패했다. 기존 별도 작업은 변경하지 않았다. `git diff --check`는 통과했다.

로컬 상세 로그와 재생성 가능한 게임/스크린샷은 `out/game-build-stage7/`와 `out/game-build-stage7-*.log`에 남긴다. 최초 실패는 `attempt-1-preparation/`에 구분했다. 비밀 인증 정보나 개인 프로젝트를 테스트 입력으로 사용하지 않는다.
