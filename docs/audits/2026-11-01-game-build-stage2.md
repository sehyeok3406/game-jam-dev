# 게임 제작 개선 2단계 완료 보고

2026-11-01. 범위는 **기본 지침의 판 관리·원본 요구 보존·사용자 설계 문서와 제작 기준 연결**이다. 실행은 기존 workflow v1·stage·session·lease·저장/히스토리 경계를 유지한다. 3단계 라이브러리 준비와 이후 build 기능은 진행하지 않았다.

## 변경 동작

| 영역             | 구현 결과                                                                                                                                                                                                                                     |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 기본 지침        | 공식 1판 보관본과 현재 2판을 구분한다. 새 요청/과거 요청의 복사에서 확인 가능한 기본값만 최신판으로 갱신한다.                                                                                                                                 |
| 사용자 편집      | 명시적 편집은 그대로 보존한다. 출처가 없거나 수정 여부를 확인할 수 없는 내용은 legacy로 보존하고 검토 안내를 표시한다. 유사도나 일부 문구만으로 자동 교체하지 않는다.                                                                         |
| 초안·기존 기록   | 초안 재개와 기존 공유 요청 편집은 텍스트를 유지한다. 과거 task·예약·실행·히스토리는 기본판 변경으로 재작성하지 않는다.                                                                                                                        |
| 비교·복원 화면   | ‘최신 기본 지침 보기’는 입력을 바꾸지 않는다. ‘기본값으로 복원’은 해당 단계의 전체 입력과 출처를 최신 기본값으로 바꾼다. 직접 입력한 문구가 기본값과 같아도 명시적으로 기본값을 선택할 수 있다.                                               |
| 적용 기록        | EffectiveInstructionsV2에 기본판/내용/hash, default·custom·legacy 출처, 사용자 대체 텍스트와 실제 적용 내용/hash를 구분해 기록한다. 보관한 defaultText를 추가 실행 지시로 취급하지 않는다.                                                    |
| 원본 요구        | HTML 단계에 정리 문서뿐 아니라 원본 선택 자료·원래 단계별 지시·선택한 시스템 문서도 전달한다. 정리 과정의 요약으로 세부 조건/금지 사항을 잃지 않도록 한다.                                                                                    |
| 설계 문서        | 새 요청의 편집 가능한 기본 구성은 게임 개요·핵심 플레이·비주얼 설계·모호한 점이다. 비주얼 문서에 아트·캐릭터/배경·카메라·HUD/메뉴·피드백/이펙트·이미지 역할과 선택 이유를 정리하도록 한다. 기존/사용자 지정 문서 구성은 자동 변경하지 않는다. |
| 원본과 제안 구분 | 공통 지침에서 사용자 지정·AI 제안·미정/상충과 근거를 구분한다. 시스템/비주얼 문서를 읽고 수정할 수 있는 제작 기준으로 사용한다.                                                                                                               |
| 이동·복원        | 문서 구조 전환·HTML 이동·과거 복원은 실제 입력/출력 경로와 중첩 단계 참조만 갱신한다. 사용자 문구·기본판·실제 적용 지시와 hash는 보존한다.                                                                                                    |
| 공동 요청        | health/state의 taskInstructionsVersion:2로 지침/맥락 지원을 구분한다. 미지원 서버로 새 provenance를 전송해 조용히 버리지 않는다. 원본 snapshot과 실행 지시 불일치도 생성 전에 거절한다.                                                       |
| 라이브러리 지침  | 이름 제한/일괄 금지 문구를 현재 기본값에서 제거했다. 최종 HTML 독립 실행과 기존 게임의 불필요한 의존성 변경 방지 지침을 유지한다. 실제 조사·설치·bundle 제공은 후속이다.                                                                      |

TaskDesignContextV1은 originalInputs/originalInstructions/designDocuments를 기록한다. 정리 단계에서 동적으로 확정된 시스템 문서는 기존 산출물 검증 후 다음 단계에 포함한다. Codex/Claude/Gemini/Grok은 같은 실행 서비스와 명세를 사용한다. 원본 입력을 덮어쓰도록 출력 범위를 넓히지 않았다.

기존 shared.ts 호환 import 한 곳을 정식 계약 import로 바꾸고 해당 architecture 예외를 제거했다. 새 예외나 검사 규칙 완화는 없다. 앱 의존성/lock 파일과 공개 버전은 변경하지 않았다.

## 남은 범위

- 문서/지침 연결은 구현했지만 실제 AI가 모든 요구를 지키거나 다양한 아트를 만들었다고 자동 판정하지 않는다. 의미·게임 전체 진행·시각 품질의 인증이나 화면 평가 기능은 이번 단계에 없다.
- 기존 세 문서와 사용자가 저장한 문서 구성을 유지한다. 새 비주얼 문서를 모든 과거 프로젝트에 자동 추가하지 않는다. 구분할 수 없는 과거 지침의 자동 최신화도 하지 않는다.
- 사용자 문서 변경은 기존 실행/예약 baseline 정책을 따른다. 실패 시 AI 산출물만 되돌리고 실행 전에 저장한 사용자 문서는 보존한다. AI가 선택한 문서를 동시에 갱신하는 explicit update target은 후속 workflow v2에서 구현한다.
- 새 source writer를 실제 AI 흐름에 연결하고 라이브러리를 조사·설치·번들하는 기능은 3~4단계다. HTML의 기존 8MB 한도와 알려진 대형 data URL 검사 결함은 이번 단계에서 변경하지 않았다.
- 네 공급자에 대한 검사는 공통 입력/실행 서비스의 합성 경로다. 실제 네 계정의 생성·다중 PC·운영 서버 부하는 후속 통합 검증이다.

상세 계약은 [요청 지침](../architecture/task-instructions.md), 구현 목표의 구분은 [게임 제작 계약](../architecture/game-builds.md), 단계별 상태는 [1차 계획](../plans/2026-11-01-game-build-phase1.md)에 유지한다.
