# 프로젝트 생성과 모드 전환 · v0.37.0

2026-10-30 이후 새 직접 생성은 [파일 구조 v2](decisions/0003-project-file-layout.md)와 빈 캔버스를 사용한다. 이름은 독립 metadata에 둔다. 기존 프로젝트는 앱 업데이트나 모드 조회로 자동 이전하지 않는다. v2 공유 자료를 로컬로 전환할 때 물리 경로 전환 journal을 사용하며 기존 이름·작성자·복구 보장을 유지한다. 새 구조를 지원하지 않는 서버에는 생성 요청 전에 업데이트를 안내한다.

## 책임과 식별

생성 폼의 이름/방식/선택 경로는 UI 상태다. `ProjectHomeService.chooseParent()`는 경로 선택만 하고, `create()`는 명시적으로 전달된 이름과 상위 폴더를 검증한 뒤 생성한다. 공통 이름 검사와 초기 자료 생성은 `core/projects`에 둔다. IPC와 preload는 runtime의 projects/collaboration 계약을 연결한다.

`ProjectLibrary`의 목록 ID는 모드 전환에 걸쳐 유지한다. 기존 ID의 문자열과 분류를 그대로 보존하며, 접두사는 모드를 판별하는 근거로 사용하지 않는다. 서버 프로젝트 ID, 참여 자격, 복귀 폴더는 별도 필드다. 기존 호출부의 `shared:<원격 ID>` 조회는 목록의 현재 연결을 해석한다. 기존 독립 로컬/공동 카드 쌍은 자동 병합하지 않는다.

## 전환 순서와 복구

`application/projects/project-mode-service.ts`는 준비 → 서버 확정 → 로컬 확정 순서를 소유한다. `desktop/projects/project-modes.ts`는 현재 세션·기존 보존 큐·인증된 client·ProjectLibrary를 연결한다. 파일 구현은 `adapters/filesystem/project-mode-files.ts`에 있으며 기존 capture/materialize/히스토리/원자 applyChanges를 재사용한다. main은 이 조립과 IPC 연결만 담당한다.

공동 직접 생성은 로컬 카드를 임시로 활성화하지 않는다. 클라이언트가 미리 생성한 고엔트로피 자격과 생성 ID를 OS 암호화 작업 기록에 저장한다. 새 전용 `/projects-mode` 경로는 구버전 서버가 이 계약을 무시하고 생성하는 것을 막는다. 서버는 같은 생성 ID·자격·입력 지문에 대해 같은 리소스를 반환하며 비밀 원문을 생성 영수증에 저장하지 않는다.

로컬 전환은 전체 서버 스냅샷과 작성자 정보를 준비 위치에 기록·다시 읽어 검증한 뒤, 콘텐츠/멤버 상태 지문으로 서버 확정 시점을 비교한다. 자료가 바뀌면 탈퇴하지 않고 다시 확인한다. 기존 복귀 폴더의 공유 시점 지문과 현재 내용이 다르면 덮어쓰지 않는다. 삭제된 파일은 atomic apply의 null 변경으로 제거하며 무관한 파일은 유지한다. 프로젝트 이름이 문서의 이전 이름과 다르면 로컬 전환 기록에서 이름 메타데이터만 갱신한다.

서버 참여 종료와 파일·목록 변경을 한 원자 트랜잭션으로 주장하지 않는다. OS 암호화 작업 기록과 서버의 제한된 전환 영수증으로 복구한다. 서버 확정 뒤 실패하면 준비본에서 앞으로 진행한다. 폐기한 참여 토큰의 정상 권한을 복원하지 않는다. 영수증 조회는 작업 ID와 256비트 증명만 검증하며 일반 자료·자격을 반환하지 않는다. 영수증은 해당 서버 프로젝트가 유지되는 동안 보관한다.

홈 목록을 읽기 전 미완료 작업을 복구하고, 서버가 없으면 보류한 채 목록·자료를 보존한다. 카드를 다시 열 때 해당 프로젝트 복구를 먼저 재시도한다. 원래 로컬 폴더를 다시 선택해도 이미 전환한 공동 카드의 연결을 열어 중복 등록을 막는다.

## 서버의 관리자와 복구 권한

새 detach는 실제 멤버 자격을 종료한다. 레거시 leave는 기존 presence/잠금 정리 동작을 유지한다. 프로젝트별 FIFO 안에서 멤버를 다시 읽고 마지막 관리자 조건을 검사한다. 멤버 제외·강등도 같은 공통 검사로 관리자 0명 상태를 금지한다. presence/잠금 정리는 저장 성공 후 수행한다.

소유자는 후임을 지정하고, 후임이 인증된 자신의 세션에서 새 복구 키를 암호화 보관한 뒤 수락한다. 마지막 확정 시 소유권/필요한 관리자 승격/복구 해시 변경/이전 멤버 종료를 함께 저장한다. 기존 소유자의 복구 키와 토큰은 이후 사용할 수 없다. 접속 여부는 활성 관리자 수와 별개이며, 후임의 온라인 수락은 소유권 인계에만 필요하다.

## 범위와 검사

다른 팀원의 공동 프로젝트와 호스팅 프로세스는 유지한다. 프로젝트 권한 인계가 서버 호스팅 이전은 아니다. 계정/기기별 새 인증 모델과 서버/로컬 전체 과거 히스토리 병합은 도입하지 않는다. 같은 참여 토큰을 복제한 세션은 같은 멤버 자격으로 취급한다.

`tests/project-modes.test.mjs`는 기본 생성 분리, 같은 카드·분류, 인계, 최신 자료, 동시 탈퇴, 응답 유실, 디스크 실패, 외부 변경을 실제 임시 서버와 파일로 검사한다. 기존 홈·세션·멤버·휴지통·런타임 검사를 유지하고 실제 Windows 패키지의 UI/IPC와 프로세스 재시작으로 확인한다. 기존 application의 이름 검증 의존을 root에서 core로 이동해 해당 아키텍처 예외 하나를 해소한다.
