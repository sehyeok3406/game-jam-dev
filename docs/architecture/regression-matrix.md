# 보존 동작과 검증 연결

## 로컬 중심 Windows 패키지 · 2026-11-14

`npm run package` 후 `node tests/local-first-packaged.mjs`와 `node tests/project-trash-packaged.mjs`를 실행한다. 전자는 격리된 공유 등록·캐시와 내장/외부 서버에서 시작 차단과 선택 정리를 검사하며 후자는 로컬 프로젝트의 휴지통 UI를 검사한다. `GAMEJAM_BUILD_EDITING=1`, `GAMEJAM_LOCAL_EXPORT=1`을 지정한 `node tests/game-build-execution-packaged.mjs`는 로컬 Git 프로젝트에서 모의 AI CLI, 실제 번들·검증, 기록 복원, 독립 실행 HTML 내보내기와 재시작을 검사한다. 아래 공유 UI와 서버 연동 패키지 시나리오는 종료 전 경로에 해당하며 현재의 공유 서버 서비스 검증은 `npm run test:server`에 포함된다.

공유 위치 링크는 기본 `npm test`의 URL/세션·배율·앵커 왕복/복제/Undo/구버전 검사를 사용한다. `test:location-links:main`은 production main/IPC와 실제 임시 서버, `test:location-links:ui`는 빌드된 renderer의 스크롤/강조/복사 메뉴, package 뒤 `test:location-links:packaged`는 Windows 종료/실행 중 수신과 실제 OS 전달·극대/극소 도형/이미지를 확인한다. UUID 프로필·임시 서버만 사용하고 OS 프로토콜의 원래 등록을 복원한다. 한 PC 검사와 실제 두 PC/메신저 검증은 구분한다. 상세 경계는 [공유 위치 링크](location-links.md)를 따른다.

7단계 실제 계정 검사는 사용자가 사용할 수 있는 Codex만 대상으로 한다. `GAMEJAM_REAL_CODEX=1` 환경에서 `node tests/game-build-codex-packaged.mjs <pixel|edit|neon|reimport|cancel>`을 명시적으로 실행한다. 기본 `npm test`에 유료/계정 호출을 넣지 않는다. `pixel`→`edit`→`reimport`는 앞 시나리오의 합성 snapshot을 사용하며 `neon`은 독립 공동 프로젝트를 만든다. `node tests/game-build-codex-browser.mjs <pixel|edit|neon|reimport> [초기 목숨]`으로 실제 내보낸 결과의 규칙·키 입력·원래 이미지 사용·승리/실패·재시작·외부 요청/오류를 확인한다. 고정 source 모의 응답으로 실제 AI 결과를 대체하지 않는다. 다른 AI 3종의 실제 계정 검증은 보류하고 공통 모의 검사와 구분한다. 진행과 발견 사항은 [7단계 기록](../audits/2026-11-03-game-build-stage7.md)을 따른다.

게임 HTML 입출력 6단계는 기본 `npm test`의 `tests/game-build-transfer.test.mjs`로 원본 상태·의미 있는 문서 비교·과거 baseline·가져온 metadata 비신뢰·바이트 보존·취소/세션/충돌·프로젝트/junction 보호·일시 잠금 재시도를 검사한다. `test:integration`은 모의 dialog와 실제 외부 파일 저장을 포함한다. Windows package 후 `node tests/game-build-native-export.mjs`로 실제 저장/취소 창·경로 보호를 확인한다. `GAMEJAM_BUILD_TRANSFER=1 GAMEJAM_BUILD_EDITING=1 GAMEJAM_PUBLIC_BUILD=1` 환경의 `tests/game-build-execution-packaged.mjs`는 실제 내보내기 버튼·native dialog·새 가져오기·새 source 제작을 local/shared에서 검사한다. AI는 모의 Claude CLI이며 bundler/registry/저장/서버는 실제다. 결과 `out/game-build-stage6/export-shared.html`과 `reimport-shared.html`에 `tests/game-build-browser.mjs <파일> 9`를 각각 실행한다. `node tests/run-html-preview-ui.mjs "out/Game Jam!-win32-x64/resources/app.asar"`는 안내를 접고 펼칠 때 남은 플레이 높이·경고·최소화·테마를 검사한다. 수행 결과·한계는 [6단계 보고서](../audits/2026-11-03-game-build-stage6.md)를 따른다.

게임 원본 수정 5단계는 `tests/game-build-editing.test.mjs`와 source workflow·approval/capability 회귀를 사용한다. 현재 source/문서/이미지 승계, 기존 수정·새 버전, 명시적 문서 target·rollback, source pointer와 입력 충돌, 고정 lock 유지, 실제 filesystem·서버 후보 복원을 검사한다. `tests/game-build-runtime.mjs`의 네 공급자 수정용 사본→실제 bundler 검사를 함께 사용한다. Windows package 뒤 `GAMEJAM_BUILD_EDITING=1`과 `GAMEJAM_PUBLIC_BUILD=1`을 설정한 `tests/game-build-execution-packaged.mjs`로 모의 CLI와 실제 Three.js·IPC·HTML 검사·로컬/공동 수정·새 버전·실패·재시작·전체 복원을 검사한다. 서버 확정과 durable client cache 전파를 구분한다. `node tests/game-build-browser.mjs out/game-build-stage5/edit-three.html 9`는 수정된 단일 파일의 Chrome/Edge 실행·이미지·키 입력·외부 요청을 검사한다. 실제 수행 결과·한계는 [5단계 보고서](../audits/2026-11-02-game-build-stage5.md)를 따른다.

게임 제작 실행 4단계는 `tests/game-build-workflow.test.mjs`와 `server-ai-start`의 v2 capability 회귀가 기본 `npm test`에 포함된다. private source 범위·단계 취소·원본 요구·source/HTML 원자 반영/rollback·기존 변환기의 버전 보존과 서버 승인/claim/완료 차단을 검사한다. 실제 고정 도구는 `tests/game-build-runtime.mjs`, Windows 전체 IPC/CLI fixture/HTML 검사/로컬 저장·재시작·공동 lease/cache/history는 package 뒤 `tests/game-build-execution-packaged.mjs`다. 후자에 `GAMEJAM_PUBLIC_BUILD=1`을 지정하면 실제 공개 Three.js 다운로드·bundle 검증을 추가한다. `tests/game-build-browser.mjs`는 그 결과 HTML을 file://로 열어 Windows Chrome/Edge의 이미지 decode·키 입력·외부 요청 0건을 확인한다. 유료 AI를 호출하지 않는다. 기존 `test:integration`의 main/IPC compatibility harness는 mock compiler receipt를 사용하며 실제 bundle 검증과 구분한다. 전체 결과·제약은 [4단계 보고서](../audits/2026-11-02-game-build-stage4.md)를 따른다.

게임 라이브러리 준비 3단계는 기본 `npm test`의 `tests/dependency-preparation.test.mjs`로 공급자 공통 파일 교환·입력 보호·교환 한도·세션 취소·앱 소유 lock/업그레이드 허용을 검사한다. 실제 도구는 `node scripts/build-game-build-runtime.mjs` 후 `node --test tests/dependency-preparation-runtime.mjs`로 검사한다. localhost registry fixture의 실제 압축/해시/다운로드·고지/API 자료·오프라인 exact 재사용·손상/설치 hook/링크/peer 충돌·실행 중 취소·중첩 모듈 해석을 사용한다. Windows package 생성 뒤 `GAMEJAM_PREPARATION_RUNTIME`을 `out/Game Jam!-win32-x64/resources/game-build-runtime`의 절대 경로로 지정해 같은 검사를 실행한다. package 빌드와 runtime 검사를 같은 도구 폴더에서 동시에 실행하지 않는다. 실제 공개 npm 표본과 계정/모의 executor 경계는 [3단계 보고서](../audits/2026-11-02-game-build-stage3.md)를 따른다. 제작 흐름 연결과 HTML bundle 검사를 대신하지 않는다.

게임 제작 지침·원본 요구의 2단계는 `tests/task-instruction-context.test.mjs`와 기존 task-instructions/gamejam-workflow/gamejam-history/document-format/result-structure/project-layout 회귀를 사용한다. 공식 기본판만 새 요청에서 갱신하는 동작, 명시적 편집·구분 불가·초안/기존 요청 보존, SHA-256/본문 일치, 원본 자료 재전달, 네 공급자의 동일 stage 입력, 사용자 문서 rollback 보호와 경로 이전을 검사한다. 실제 화면은 `npm run test:gamejam-history`, `npm run test:gamejam-validation`; 실제 Windows package는 `npm run package` 후 `node tests/game-build-instructions-packaged.mjs`다. 계정·유료 AI를 호출하지 않는다. 새 기본 구성이 네 문서여도 기존 세 문서/사용자 구성은 보존한다.

게임 원본 저장 v1은 `node --test tests/game-build-storage.test.mjs tests/game-build-server.test.mjs`로 경로·hash·완성 묶음·불변 revision·copy/move/delete/history·중단 복구·구버전 차단·quota·HTTP admission·SQLite/백업 복원을 검사한다. 기본 `npm test`에 포함된다. 큰 메모리를 사용하는 `node tests/game-build-large.mjs`는 전체 단위 검사와 별도로 실행한다(약 60.86MB·32 revision의 실제 HTTP/DB/백업 복원). Windows package는 `npm run package` 후 동일 결과물로 `node tests/game-build-packaged.mjs`를 실행한다. AI/registry 다운로드나 유료 계정을 사용하지 않는다. 원본 writer가 아직 AI workflow에 연결되지 않았다는 [1단계 한계](../audits/2026-11-01-game-build-stage1.md)를 함께 해석한다.

게임 제작 확장 0단계는 `node tools/game-build-stage0/run.mjs`와 `node tools/game-build-stage0/summarize.mjs`로 별도 검증한다. 공개 npm·격리 설치·현 PC의 Chrome/Edge와 Electron·기존 package의 Node runtime을 사용하며 실제 AI·운영 서버는 사용하지 않는다. 기본 CI 검사에 네트워크/설치 브라우저 의존을 추가하지 않는다. 현재 정책의 실패 사례도 측정하므로 [0단계 보고](../audits/2026-11-01-game-build-stage0.md)와 함께 해석한다.

프로젝트 파일 구조 v2는 `tests/project-layout.test.mjs`에서 빈 시작, 문서 경로, 속성에 의한 AI 문서 묶음, ID·링크·섹션 보존, durable 이전 재개, 과거 복원, 관리자 전환·구버전 차단·오프라인 신규 문서·탐색기 사본 준비를 검사한다. 실제 Windows UI/IPC·명시적 공유 전환·재시작·홈 탐색기 메뉴·새 프로젝트 빈 시작은 `tests/projects-packaged.mjs`의 확장 경로를 사용한다. 기본 홈·모드 전환·mirror·복사·AI 검사를 함께 유지한다. 정책은 [ADR 0003](decisions/0003-project-file-layout.md)을 따른다.

Grok 공급자 검증은 `tests/grok-provider.test.mjs`, 기존 run-service/coordinator·초안·협업 회귀 및 `test:ai-queue`·`test:integration`의 Grok mock 경로를 사용한다. 공식 CLI 검증은 `GROK_TEST_EXECUTABLE`을 지정한 `node --test tests/grok-native.test.mjs`로 실행한다. localhost 합성 모델로 실제 `write` 목록·입력 전달·외부 읽기/쓰기 차단을 확인하며 실제 계정이나 유료 API 검증을 대신하지 않는다. `GAMEJAM_AI_PROVIDER=grok-cli`로 `tests/ai-queue-packaged.mjs`를 실행하면 같은 packaged 예약·공동 결과 검증을 Grok mock adapter로 수행한다.

프로젝트 이름과 공유 사본은 `tests/project-names.test.mjs`에서 PC·서버 이름 경쟁, 참여 전 검사와 응답 유실 재시도, 기존 중복 보존, 전체 디렉터리 이동·중단 복구·대소문자 개명을 검사한다. `project-trash.test.mjs`는 복원 이름 충돌의 무부작용을 확인하고 `projects-packaged.mjs`는 실제 홈 메뉴 이동·초안·중복 거절·재시작 경로를 확인한다. [ADR 0004](decisions/0004-project-names-and-shared-folders.md)를 따른다.

문서·HTML 이름 통일은 `document-names.test.mjs`, `file-names-integration.test.mjs`, `file-names-server.test.mjs`, `document-save-queue.test.mjs`와 최종 패키지의 `document-names-packaged.mjs`·`unified-file-names-packaged.mjs`로 확인한다. 실제 임시 서버/두 클라이언트·디렉터리·격리 프로필을 사용하며 구버전·권한·잠금·오프라인·재시도·복원·일괄 적용을 포함한다. [ADR 0005](decisions/0005-document-file-names.md)를 따른다.
