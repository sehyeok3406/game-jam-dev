# ADR 0004 · 프로젝트 이름과 공유 사본 경로

- 날짜: 2026-10-31
- 상태: 채택

## 문제와 제약

공유 사본을 UUID 폴더에만 보관하면 탐색기에서 프로젝트를 구별하기 어렵다. 이름을 폴더 이름으로 쓰더라도 원격 프로젝트의 영구 식별과 참여 자격을 이름에 결합해서는 안 된다. 기존 중복 이름, UUID 사본, 다른 PC에서의 이름 변경과 미전송 자료도 보존해야 한다.

## 결정

이 PC의 활성 프로젝트 이름은 로컬·공유와 저장 상위 위치·홈 분류에 관계없이 하나의 이름 공간을 쓴다. 비교는 양끝 공백 제거·NFC·대소문자 무시이며 공통 core가 Windows 파일 이름 규칙을 검사한다. 자기 목록 ID는 제외한다. 새 생성·등록·이름 변경·모드 전환·복원은 확정 전에 검사하고 이름 예약은 실패해도 해제한다. 휴지통 이름은 점유하지 않지만 복원할 때 다시 검사한다. 동일 서버의 활성 공유 이름은 서버 persist의 공통 이름 큐에서 검사한다. 기존 프로젝트별 큐와 권한 검사는 유지한다.

공유 사본의 root는 ProjectLibrary의 비공개 sharedRoot에 저장한다. 원래 로컬 복귀 위치 localRoot와 다르다. 모든 접속·캐시·복사·휴지통·탐색기 경로는 같은 filesystem 경로 resolver를 사용한다. 새 사본은 shared-workspaces/프로젝트 이름에 만들고 ID는 폴더 접미사로 붙이지 않는다. 기존 폴더는 소유권 표식 없이 임의로 재사용하지 않는다. 같은 프로젝트의 재가입으로 목록 ID가 달라져도 표식의 서버 주소와 원격 ID가 일치하면 사본을 재사용한다. 다른 서버의 동명 사본은 거절한다. 원격 ID·목록 ID·암호화 자격은 유지한다.

기존 UUID 사본과 원격 이름 변경 후 폴더는 자동 개명하지 않는다. 홈의 ‘공유 사본 폴더 이름 정리’가 기존 viewer·저장·감시·세션 정지 경계를 거쳐 디렉터리 전체를 이전한다. 원본/목적지/디렉터리 identity를 먼저 journal에 기록하고 원자 rename 뒤 root 기반 초안·설정을 재연결하고 registry를 확정한다. 대소문자만 바뀌는 이동은 같은 journal에 기록한 중간 폴더를 거친다. 캐시 메모리를 무효화한다. 현대 저장 큐와 개인 설정 scope는 프로젝트 ID이므로 그대로 유지한다. 기존 root 초안은 새 키로 복사하고 원본도 보존한다.

시작 시 미완료 이동을 재개한다. identity 불일치·junction·다른 목적지·초안 충돌은 덮어쓰지 않고 journal을 보존한다. 미완료 프로젝트의 일반 ensure는 이동을 우회하지 않는다. 사용자 선택 로컬 폴더는 이동하지 않는다.

참여는 초대 검증 후 최소 ID·이름·이름 버전을 사전 조회하고 PC 이름 검사를 통과한 뒤 멤버를 만든다. 최종 요청도 서버 프로젝트별 큐 안에서 버전을 검사한다. 참여 요청 ID와 토큰은 요청 전에 OS 암호화 저장하며 응답 유실 재시도는 같은 멤버를 반환한다. 받은 자격은 활성화 전에 registry에 보관한다. 복구도 복구 키 인증 후 이름을 먼저 조회하고 충돌 검사를 통과해야 토큰/복구 키를 교체한다. 구형 서버는 새 생성·이름 변경·참여·복구 전에 업데이트를 안내하며 기존 문서 연결·동기화 경로는 유지한다.

## 대안과 이유

- 이름+UUID 폴더: 충돌 처리는 단순하지만 사용자가 요청한 이름만 표시하는 구조와 다르다.
- UUID 제거 및 이름을 영구 ID로 사용: 원격 이름 변경·재접속·권한·히스토리 연결을 깨뜨리므로 사용하지 않는다.
- 앱 업데이트 시 일괄 이동: 사용 중인 파일·미전송 초안과 다른 PC의 로컬 충돌을 일괄 판단할 수 없어 명시적 프로젝트별 이동을 선택했다.

## 이행 예외와 보장 범위

기존 중복 이름과 외부에서 변경된 이름은 관찰 정보로 수용하며 홈에 충돌을 표시한다. 이를 이유로 문서 열기·저장·동기화를 중단하지 않는다. 새 이름 확정과 폴더 정리는 충돌 해결 후 수행한다. 원격 관리자는 다른 PC의 로컬 이름을 알 수 없다. 이름 전역 유일성은 PC 목록별 및 협업 서버별이며 인터넷 전체의 유일성을 뜻하지 않는다. 서버 저장 디렉터리는 계속 ID를 사용한다.

서버와 PC의 저장은 분산 트랜잭션이 아니다. 참여 응답 유실은 durable 요청으로 재개한다. 기존 복구 API의 키 교체 직후 전송이 유실되는 문제는 기존 복구 프로토콜의 한계이며 이번 변경은 이름 충돌 때문에 키를 교체하는 일을 방지한다. 물리 폴더 이동은 대상 자료와 합치지 않으며, 충돌을 자동 삭제로 해결하지 않는다.

## 검증과 재검토

project-names·home·mode·copy·trash·layout·collaboration 회귀와 strict 타입/아키텍처 검사를 사용한다. 격리 Windows 패키지에서 실제 홈 메뉴·이름 충돌·전체 사본 이동·초안·재시작·내장 서버·탐색기 경로를 확인한다. 웹 편집기나 다중 쓰기 프로세스를 지원할 때 이름 예약의 범위와 경로 소유권을 다시 검토한다.
