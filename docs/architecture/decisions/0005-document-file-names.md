# 0005 · 문서·HTML의 표시 이름과 실제 파일명 통일

- 날짜: 2026-11-01
- 상태: 채택·개인/공동 Markdown·HTML·일괄 통일·생성 경로 구현.
- 근거: 사용자의 이름 통일 요청과 [구현 계획](../../plans/2026-10-31-unified-file-names.md).

## 문제와 결정

캔버스 제목만 바뀌면 탐색기의 파일명, 검색과 AI 입력 경로가 달라진다. ADR 0003의 ‘제목 편집으로 파일을 이동하지 않는다’는 정책을 사용자 Markdown과 관리되는 HTML 진입 파일의 명시적 이름 확정에 대해 변경한다. 기존 파일은 열기만으로 바꾸지 않는다.

1. `contracts/document-names.ts`가 개명/검사/일괄 적용 계약을, `core/documents/file-name.ts`가 이름·충돌 규칙을 소유한다. 한글·공백/NFC, Windows 예약명·금지 문자·대소문자 충돌을 동일하게 검증한다. 사용자 개명에서 문자를 몰래 삭제하지 않는다. 생성·복제·일괄 제안의 충돌은 `(2)`처럼 읽을 수 있는 최종 이름을 제시한다.
2. `DocumentNameService`와 읽기 전용 application planner는 ID·원래 내용·영향 파일을 검증한다. Electron의 session/mutation/history와 공동 reducer·서버 명령 큐를 재사용한다. UI는 주입된 runtime만 호출한다. 본문 자동 저장은 기존 저장 큐와 원래 제목을 사용하고, 이름은 Enter·Ctrl+S·편집 완료에서 별도로 확정한다. 일반 `documents:save`의 기존 제목 입력 계약은 호환성을 위해 남기며 새 UI의 개명 우회 경로로 사용하지 않는다.
3. Markdown은 같은 디렉터리에서 개명하며 안정 ID·원본 H1·본문·사용자 metadata를 보존한다. 경로 기반 레거시 ID는 frontmatter에 고정한다. Markdown 파서와 기존 typed metadata 변환을 재사용하여 링크·출처·섹션·칸반·UI 설명 문서 연결을 갱신한다. 일반 문자열과 코드의 이름을 일괄 치환하지 않는다. 고정 `project.md`는 기존 v2 구조 정리를 선행하며 내부 AI 작업·HTML 관리 문서는 사용자 문서 개명에서 제외한다.
4. HTML 이름 변경은 분류/기능/버전 폴더와 리소스를 유지하고 진입 파일명만 바꾼다. 고유 source ID·초기 identity 경로·레거시 버전을 보존한다. 목록은 레거시 진입점 또는 관리 문서/이력에 등록된 HTML만 노출하여 리소스 HTML을 새 결과로 오인하지 않는다. 같은 콘텐츠의 개명은 ReactFlow 노드와 실행 중 iframe을 유지한다. 기존 결과 갱신·분류 폴더 이동·새 프로젝트 복사는 실제 진입 경로를 사용한다.
5. HTML의 해석 가능한 정적 URL 속성은 파싱된 소스 위치로 갱신한다. 지원하지 않는 script/style 참조의 변경 필요가 발견되면 개명을 거절한다. 동적 JavaScript를 실행·추론해 자동 교정하지 않는다. `<title>`과 게임 내부 제목은 사용자 콘텐츠로 보존한다. 임의 동적 코드 전체에 대한 무결성 보장은 이번 기능에 포함되지 않는다.
6. 논리 `.canvas/file-names.json`에 `{id, kind, path, name, originalPath, previousPaths}`를 저장한다. v2 실제 위치는 기존 변환에 따라 `.gamejam/project/canvas/file-names.json`이다. 레거시 구조 alias와 별개로 ID를 통해 여러 번 개명·옛 이름 재사용을 구별한다. 본문 저장 큐는 원래 경로·ID·base를 검증하고 파싱된 링크를 재연결한다. 사용자가 이름을 수정하지 않은 미전송 본문만 최신 확정 이름을 채택한다. 미확정 이름과 본문 초안의 의도를 보존하며 다른 ID의 파일을 덮어쓰지 않는다.
7. `documentNamesVersion:1`을 협상한다. 공동 개명은 온라인에서만 가능하며 미전송 동기화 변경, 다른 사용자의 영향 파일 잠금, AI 실행/예약, 오래된 원본을 거절한다. 기존 서버 권한·revision·request receipt·SQLite 확정을 사용한다. 편집자는 개명으로 계산된 완료 AI 명세의 경로 참조를 함께 바꿀 수 있으나 일반 AI 명세 편집은 관리자 권한을 유지한다. 이름 이력이 있는 프로젝트는 이를 해석하지 못하는 구버전 클라이언트의 쓰기를 거절한다. 서버 개명 미지원 시 로컬 사본만 바꾸는 대체 저장은 하지 않는다.
8. 파일 adapter는 MD/HTML 이동과 대소문자 변경을 감지하여 `.gamejam/local/document-names/pending.json`에 원본·목표를 durable 기록한 뒤 기존 `applyChanges`를 사용한다. 대소문자 변경은 기존 물리 경로를 비운 뒤 목표 이름으로 기록한다. 실패·다음 열기에서는 알려진 원본/목표 bytes만 원복한다. 외부 변경은 journal을 남기고 보존하며 session 전환 후 새 프로젝트에 쓰지 않는다. 공유 mirror 열기도 동일한 복구를 먼저 수행한다.
9. Undo/Redo는 개명·참조를 하나의 기록으로 되돌린다. 일반 본문/HTML 과거 기록은 현재 이름의 같은 ID로 복원한다. 명시적 개명 기록은 경로 이동 자체를 되돌린다. 과거 불변 history bytes는 다시 쓰지 않는다. 재사용된 옛 경로의 모호한 삭제 복원은 다른 문서를 삭제하는 대신 거절한다.
10. 설정의 ‘파일 이름 통일…’은 현재 프로젝트의 읽기 전용 미리보기·중복 후보·사용자 최종 이름·영향 파일·v2 선행 조건을 제공한다. 적용 시 snapshot 기준 해시와 최신 권한/잠금을 다시 검사하고 승인한 항목을 한 명령으로 반영한다. 구조 정리와 이름 통일은 각각 확정되며 전체를 단일 OS 원자 작업이라고 표시하지 않는다.
11. 직접 작성·가져오기·복제·프로젝트 간 복사·게임 UI 설명 문서는 읽을 수 있는 사용자 제목으로 파일을 할당한다. HTML 생성은 같은 버전 폴더 안의 이름 있는 `.html`을 사용한다. AI는 승인/예약된 출력 경로를 실행 뒤 변경하지 않으며, 게시 단계에서 사용자 Markdown의 표시 제목을 확정된 파일명과 맞춘다. 내부 task/관리 파일의 고정 이름은 유지한다.

## 대안과 이행 범위

표시 제목만 저장하는 기존 방식은 불일치를 남기므로 채택하지 않았다. 원시 문자열 전체 치환은 코드와 본문을 손상시키므로 사용하지 않는다. 레거시 구조 alias를 개명 체인으로 재활용하는 방식은 재개명/이름 재사용을 구분하지 못해 별도 ID 이력을 사용한다. 모든 파일을 자동 이전하는 방식 대신 명시적 미리보기·적용과 기존 구조 정리를 재사용한다.

OS 탐색기의 직접 개명 자동 추적, 임의 동적 코드 교정, 원격 웹 편집기의 구현은 범위 밖이다. HTML 이름 입력 실패는 현재 입력을 유지하며 Markdown 본문/이름 초안은 기존 로컬 초안 저장을 사용한다. 이 기능으로 서버 로그인·구독이 개인 기능의 선행 조건이 되지 않는다.

## 검증과 재검토

`document-names.test.mjs`, `file-names-integration.test.mjs`, `document-save-queue.test.mjs`는 실제 임시 파일·이름 규칙·ID·링크·과거 기록·대소문자 역복원·중단 복구·오프라인 초안을 검사한다. `file-names-server.test.mjs`는 실제 서버와 두 클라이언트의 동시 개명, 본문 재접속, 잠금·뷰어·구버전 차단, 동일 요청 재전송과 서버 재시작을 확인한다. 기존 생성/가져오기/프로젝트 복사/HTML·AI·공유 명령 검사를 함께 유지한다.

최종 Windows 패키지의 `document-names-packaged.mjs`와 `unified-file-names-packaged.mjs`는 실제 이름 입력, 취소·오류, 파일·참조·iframe, 일괄 미리보기/확정·Undo/Redo·구조 정리·전체 재시작을 검사한다. 임시 프로젝트와 격리 프로필만 사용한다. 새 파일 형식·동적 의존성 분석·오프라인 구조 변경을 지원할 때 경로 계약과 복구 보장을 재검토한다.
