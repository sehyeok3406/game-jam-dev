# ADR 0007: 공동 프로젝트 위치 링크와 문단 앵커

- 날짜: 2026-11-03
- 상태: 채택

## 문제와 제약

기존 `gamejam://document/...`와 `gamejam://file/...`는 열린 프로젝트 안에서 문서를 연결한다. 다른 앱에서 받은 주소로 프로젝트를 열거나 그림·텍스트·HTML 및 문단으로 이동하는 계약은 없었다. 프로젝트별 참여 자격, 저장 큐, 세션 수명, 개인 로컬 기능의 독립성을 보존해야 한다.

## 결정

외부 주소는 `gamejam://open?v=1&project=<uuid>&kind=<document|file|html|drawing>&id=<id>[&block=<uuid>]`를 사용한다. 서버 주소·토큰·초대 코드·복구 키·절대 경로·본문을 포함하지 않는다. 받는 PC의 ProjectLibrary에서 이미 참여한 프로젝트를 찾고 저장된 자격으로 온라인 lifecycle/state를 확인한다. URL로 자동 참여하거나 서버 주소를 바꾸지 않는다. 같은 ID의 연결이 여러 개면 현재 연결을 우선하고, 모호하면 프로젝트를 먼저 선택하도록 안내한다. 다른 서버의 동일 프로젝트 ID를 현재 세션으로 잘못 처리하지 않도록 저장된 자격과 활성 자격도 비교한다.

계약은 contracts, URL 검증/매칭/배율 계산은 core, 열기·발급 순서는 application의 LocationLinkService가 소유한다. ProjectHomeService의 기존 프로젝트 열기를 사용하고 desktop은 ProjectLibrary·인증 client·프로토콜/IPC를 조립한다. 화면은 주입된 runtime으로만 요청한다. 열린 프로젝트와 연결된 sessionId/epoch를 IPC에서 검사하며 기존 property/mutation 큐·편집 flush와 프로젝트 보존 경로를 재사용한다.

Windows는 설치 앱을 `gamejam` 프로토콜 처리기로 등록한다. Electron의 userData별 단일 인스턴스 잠금으로 기존 창에 전달하고, 테스트 사용자 프로필은 별도 실행을 유지하며 OS 등록을 덮어쓰지 않는다. 최초 실행·second-instance·open-url을 같은 inbox에 넣는다. inbox는 최신 미처리 주소 한 개를 보관하고 ID가 같은 확인 응답만 제거한다. renderer 준비 전에 받은 주소도 pending 조회로 읽으며 오류는 홈·프로젝트 공통 안내창에 표시한다. 2026-11-05 사용자 지시에 따라 수동 붙여넣기 버튼/패널을 제거하고 직접 링크 열기와 오류 안내를 유지한다.

영속 문단 위치는 Tiptap의 보이지 않는 inline atom `locationAnchor`로 보관한다. Markdown에서는 `<!--gamejam:block:<uuid>-->`, 캔버스 텍스트에서는 `{type:'locationAnchor',attrs:{id}}`로 직렬화한다. 앵커는 사용자가 문단 링크를 처음 복사할 때 기존 편집/저장 명령으로 추가한다. 임의 HTML 렌더링은 허용하지 않고 읽기 화면에서는 이 주석만 비활성 span으로 변환한다. 일반 문단·제목·목록·표 셀·인용을 지원하며 codeBlock이나 여러 문단에 걸친 선택은 거절한다.

기존 앵커의 문자 앞 편집은 ID를 유지한다. 같은 문서에 앵커를 포함해 복제하면 기존 위치를 매핑해 원본 ID를 유지하고 복제본에 새 ID를 발급한다. 잘라내기/이동·문단 분할/병합에서는 atom이 포함된 쪽으로 식별이 이어진다. 여러 앵커가 한 문단에 합쳐지면 자동 선택하지 않고 정리를 안내한다. 다른 문서·텍스트 객체의 앵커는 부모 ID와 함께 식별하므로 부모를 복제한 사본은 원본 링크 대상이 아니다. 원문/외부/AI 편집으로 앵커가 삭제되면 위치를 추측하지 않고 문서까지 보여준 뒤 안내한다. 앵커 삭제·복원은 기존 본문 및 그림 히스토리를 따른다.

서버는 `locationAnchorVersion:1`을 광고한다. 앵커를 보유한 snapshot의 조회·수정·오프라인 반영은 이를 지원하는 클라이언트만 허용한다. UI는 지원 서버에서만 문단 링크 생성을 노출하고, 구버전 서버의 앵커 저장은 성공으로 간주하지 않는다. 새로운 DB·앵커 저장소·권한 경로를 추가하지 않는다.

대상은 현재 소속 캔버스에서 찾는다. 도형/이미지/그림은 회전 후 실제 표시 경계와 여백을 화면에 맞추며 고정 15%/25% 하한으로 자르지 않는다. 작은 대상은 자동 확대 상한 100%, 외곽 강조 최소 32px를 적용한다. 문서·텍스트·HTML은 읽기 높이와 내부 스크롤을 우선하고 문단은 그 안에서 찾는다. 약 300ms의 취소 가능한 카메라 이동을 사용하며 사용자 pointer/wheel 입력은 대기 이동과 강조를 해제한다. 후행 초기 fit 작업은 viewport intent가 바뀌면 실행하지 않는다. 대상 배치나 다른 참여자의 화면은 바꾸지 않는다.

## 대안

- HTTPS 안내 페이지: 메신저 호환성에는 유리하나 호스팅이 필요하다. 현재는 커스텀 프로토콜의 직접 열기를 제공한다.
- URL에 서버 주소/초대 자격 포함: 자동 연결은 쉽지만 링크가 권한이나 자격 전송 대상이 되는 문제를 피하기 위해 채택하지 않았다.
- 줄 번호/문자 offset/문장 검색: 앞쪽 편집·중복 문장에 취약하다. 문단의 명시적 ID를 사용한다.
- 별도 앵커 metadata: Markdown 자체를 유지하기 쉽지만 외부 본문 교체 후 동일 문단을 보장하기 어렵다. 본문과 함께 이동하는 atom을 택했다.

## 제약과 검증

영속 ID가 없는 파일은 프로젝트 상대 경로로 연결하며 개명/삭제 후 같은 경로 재생성의 동일성을 보장하지 않는다. HTML은 기존 source identity와 이름 이력을 재사용한다. 링크만으로 HTML을 실행하거나 파일을 외부 앱에서 실행하지 않는다. 임의 파일/HTML 내부 DOM·문자 일부의 영구 범위 추적·오프라인 권한 검증·공유 URL 호스팅은 이번 범위가 아니다.

`location-links.test.mjs`, `location-anchors.test.mjs`, production main/IPC 검사와 실제 renderer·Windows package 검사를 연결한다. 실제 두 PC와 사용 메신저의 클릭 처리는 한 PC의 격리 프로필·OS 프로토콜 검사와 구분해 보고한다. 앵커 호환 계약·서버 주소 재연결 정책을 바꾸면 이 결정을 재검토한다.
