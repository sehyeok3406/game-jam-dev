# ADR 0010 로컬 사운드 원본과 재생

- 날짜 2026-11-12
- 상태 채택

## 문제와 제약

사운드 원본은 파일당 최대 50 MiB다. 프로젝트의 Markdown 편집 기록과 Git 또는 Git LFS 파일 공유를 활용하면서 긴 원본에서 구간 탐색을 지원해야 한다. 초기 지원 범위는 로컬 프로젝트다.

## 결정

- 원본은 `assets/audio/<SHA-256>.<ext>`에 저장한다. Markdown의 `audio_asset`에 경로, 원래 이름, 크기를 기록한다. 프로젝트 간 로컬 복사는 대상 프로젝트에 같은 원본을 준비한 뒤 기존 복사 명령을 사용한다.
- Filesystem adapter가 입력 헤더·크기·해시를 검사하고 원본을 로컬 객체로 준비한다. repository 반영은 MD 생성 전에 원본을 준비하고 마지막 참조가 사라질 때 활성 원본을 제거한다. 편집 기록에서 복원할 원본은 `.gamejam/local/audio-objects/`에 보존한다. Git LFS 포인터가 남은 경우 활성 경로에 유지한다.
- 데스크톱은 현재 프로젝트의 원본에만 세션 범위 재생 URL을 발급한다. Electron 프로토콜에서 Range 응답을 스트리밍하고 세션이 끝나면 접근을 종료한다.

## 대안과 영향

원본을 기존 문자열 스냅샷에 Base64로 넣는 방식은 편집·히스토리·협업의 메모리 및 전송 비용을 함께 늘린다. 원본의 외부 절대경로를 기록하는 방식은 프로젝트 이동과 Git 복제 후 재생을 보장하기 어렵다. 이 결정은 기존 텍스트 스냅샷과 원본 파일을 함께 사용하는 로컬 경로를 추가한다.

활성 원본은 같은 프로젝트 안에서 동일 해시와 확장자끼리 재사용된다. 마지막 노드 삭제는 편집 기록을 사용한다. 로컬 객체는 자동 정리하지 않으며 삭제 전 원본 복원은 해당 로컬 기록에 의존한다. 앱 내 공동 프로젝트로 전환하거나 복사할 때 사운드 노드가 있으면 이를 안내하고 중단한다.

## 검증과 재검토

`tests/audio-assets.test.mjs`로 바이트 보존과 복원·형식 검사를 확인한다. Windows 패키지에서 실제 MP3의 드롭·파형·구간 탐색·음량·삭제와 복원을 확인한다. 공유 서버에서 사운드를 지원하거나 편집 기록 보존 정책을 바꿀 때 원본 배포·객체 보존 기간·복원 책임을 다시 검토한다.
