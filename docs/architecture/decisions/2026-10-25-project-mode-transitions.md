# ADR: 프로젝트 정체성과 작업 방식의 분리

상태: v0.37.0 적용. 결정일: 2026-10-25.

## 문제

기존 공유는 로컬 폴더 카드와 별도 서버 카드를 만든다. 나가기는 presence만 지우고 예전 로컬 폴더를 다시 열며, 생성자는 역할과 복구 권한이 고정돼 있다. 이를 단순한 화면 표시 변경으로 처리하면 최신 자료 유실, 관리자 없는 공동 프로젝트, 이전 복구 키에 의한 권한 재획득이 발생할 수 있다.

## 결정과 대안

- 목록 ID는 불투명한 고정 값으로 유지하고 모드와 원격 연결을 분리한다. 전체 레거시 ID를 강제로 UUID로 치환하는 대신 기존 ID와 분류를 유지한다. 레거시 접두사 충돌은 새 ID를 할당하고, 원격 조회는 명시적인 findShared로 처리한다. 이미 독립한 과거 사본은 자동 병합하지 않는다.
- 공동에서 로컬로 전환하면 내 참여자 자격만 종료한다. 팀 전체 프로젝트 삭제나 모든 팀원의 모드 변경은 수행하지 않는다. 계정/기기 인증 모델을 새로 추가하는 대안도 이번 범위에서 제외한다.
- 서버와 PC의 분산 원자 저장을 가장하지 않는다. 검증한 준비본 → 버전 확인과 서버 확정 → 로컬 확정 순서를 사용하고, 암호화 작업 기록과 제한된 영수증으로 재개한다. 응답 실패를 무시하는 leave는 전환 대안으로 사용하지 않는다.
- 소유자 고정 정책을 인계 가능한 소유권으로 확장한다. 후임이 복구 키를 자기 PC에 안전하게 보관한 뒤 수락하고, 최종 확정에서 소유권과 키 해시를 함께 바꾼다. 단순한 관리자 승격만 하고 옛 owner/복구 키를 남기는 대안은 거부한다. 수락 재시도는 같은 인계 ID의 같은 복구 키를 사용한다.
- 모든 권한 종료·강등·제외에서 서버 FIFO가 관리자 최소 1명을 검사한다. UI 조건이나 접속 중인 관리자 수로 대체하지 않는다.
- 개인 캔버스 선택·뷰포트는 고정 목록 ID로 연결하고 이전 경로 설정을 첫 조회 때 이전한다. 초안·저장 큐는 모드와 권한 범위를 계속 유지한다. UI 상태 보존을 이유로 재전송 큐를 공유하지 않는다.

## 영향과 검증

새 프로젝트 생성 화면은 이름 검사와 경로 선택/최종 생성을 분리한다. /projects-mode 전용 생성 프로토콜과 projectModeVersion: 1 기능 협상으로 구형 서버의 조용한 우회를 막는다. UI → application → desktop/adapters 및 서버의 기존 큐·저장 계층을 재사용한다.

전환 실패 주입, 인계/동시 탈퇴, 생성 응답 유실, 레거시 ID 충돌, 개인 설정, 전체 자동 검사와 실제 Windows 패키지 검증을 연결한다. 세부 책임과 제한은 ../project-mode-transitions.md 및 저장소의 PROJECT_MODE_TRANSITION_PLAN.md를 참고한다.
