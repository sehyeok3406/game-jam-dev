# 0001. 구현 지침과 아키텍처 검사의 연결

- 날짜: 2026-10-25
- 상태: 채택

## 배경

리팩토링 이후 영역별 설계 문서와 계약/runtime 검사는 있으나 루트 AGENTS.md는 배포 지침만 담고 있었다. 구현 요청마다 사용자가 설계 의도를 다시 설명하지 않아도 책임 배치와 검증 기준이 유지되어야 한다. 기존 레거시 의존성이 남아 있어 목표 구조 전체를 즉시 강제하면 기능 개발과 무관한 대규모 이동이 발생한다.

## 결정과 이유

짧은 루트 AGENTS.md, 현재 설계와 영역별 문서를 연결하는 안내, 직접 의존성 검사와 정확한 기존 예외 목록을 함께 사용한다. 문서는 책임과 이유를 설명하고 자동 검사는 새 구조 위반을 발견한다. 기존 계약/UI 정적 검사는 전용 아키텍처 테스트로 모으고 runtime 동작 검사는 유지한다.

기존 예외는 파일·대상·발생 수를 고정하며 해소되면 제거한다. 예외 자동 재생성 기능은 제공하지 않는다. 불가피한 예외 추가는 이유·제거 조건과 설계 근거를 같은 변경에 포함한다. 일반 구현마다 사용자 승인이나 별도 계획을 요구하지 않는다.

## 검토한 대안

- AGENTS.md 하나에 모든 설계를 넣기: 반복되는 문서가 길어지고 현재 설계와 이력이 섞인다.
- 별도 스킬만 추가하기: 매번 필요한 저장소 공통 기준을 선택적인 절차에 의존하게 된다.
- 목표 의존 방향을 즉시 전면 강제하기: 기존 업무 모델 이동과 동작 회귀 검증이 필요하므로 이번 지침 작업의 범위를 넘는다.

## 영향과 검증

제품 실행 코드·배포 절차는 바꾸지 않는다. 검사기는 기존 TypeScript 개발 의존성을 사용하고 npm test 및 CI에 연결한다. 금지 import, 재귀 탐색, 로컬 별칭, type/dynamic import와 require, 예외 증가·감소·중복을 검사기 테스트로 확인한다. 현재 소스의 예외 목록도 실제 스캔과 일치해야 한다.

직접 의존성 검사로 웹 재사용성이나 업무 정확성을 보증하지 않는다. 간접 Node 결합 제거, 새 플랫폼 도입 또는 반복되는 누락이 발생하면 검사 범위와 문서를 함께 재검토한다. 별도 폴더 지침·스킬은 실제 반복 절차가 필요해질 때 도입한다.
