# Game Jam! 로컬 저장과 화면 갱신 PRD

2026-11-17 · 구현 검토안 · 기준 소스 `54b6567`

## 목표

메모를 쓰거나 펜으로 연달아 그리는 동안 입력을 화면에 즉시 반영한다. 디스크에는 복구용 초안과 프로젝트 원본을 각자의 주기에 맞춰 저장한다. 화면을 갱신할 때는 변경된 파일이나 항목만 반영해 프로젝트 크기에 따라 편집이 느려지는 일을 줄인다.

대상은 Windows 데스크톱의 로컬 프로젝트다. 우선 Markdown 본문, 펜·도형·지우개, 캔버스 텍스트에 적용한다. 프로젝트 폴더를 외부 편집기에서 수정하거나 AI 결과를 받아오는 경우도 같은 화면에서 다룬다.

## 현재 동작과 문제

| 작업                       | 현재 소스에서 확인한 동작                                                                                                                    |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Markdown 입력              | 0.3초 유휴에 복구 초안을 저장한다. 1초 유휴 또는 3초 간격으로 미저장 내용을 확인해 원본 저장을 요청한다.                                     |
| 펜·도형·지우개             | 펜과 도형은 그리는 중 약 0.3초 간격으로 복구 초안을 남긴다. 획·도형 생성이나 지우개 동작이 끝나면 그림 명령을 확정하고 히스토리를 기록한다.  |
| 캔버스 텍스트              | 내용 변경 때마다 초안 저장을 요청하고 0.45초 유휴에 확정 저장을 요청한다.                                                                    |
| Markdown 저장 뒤 화면 갱신 | 저장 응답으로 문서가 갱신된다. 본문 변경 알림은 별도로 전체 갱신을 일으켜 문서·섹션·HTML 결과 목록을 다시 읽는다.                            |
| 그림 되돌리기              | 기준 소스에서 그림만 변경된 기록은 그림 범위의 읽기와 화면 갱신을 사용한다. 화면에서 되돌리기를 시작하기 전 등록된 편집기의 저장을 기다린다. |

## 목표 동작

| 동작                           | 사용자에게 보이는 결과                                                                                                                                                  |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 입력·완료된 제스처             | 변경이 즉시 화면에 나타난다. 펜 한 획, 도형 하나, 한 번의 지우개 동작은 각각 한 번의 되돌리기 단위다.                                                                   |
| 복구 초안 · 합의한 기본값      | 첫 미저장 변경부터 **30초**를 세고, 이후 미저장 변경이 계속 생기면 **30초마다** 변경된 대상의 최신 초안을 보관한다. 마지막으로 보관한 초안과 같으면 쓰기를 생략한다.    |
| 원본 자동 저장 · 합의한 기본값 | 활성 프로젝트에서 마지막 편집 후 **2분간 편집이 없으면** 대기 중인 변경을 모아 확정한다. 화면 이동, 확대·축소, 단순 선택은 편집 시간에 포함하지 않는다.                 |
| 즉시 원본 저장                 | `Ctrl+S`, 프로젝트 전환, 정상 종료, AI 실행 전에는 필요한 원본 저장을 즉시 시작하고 성공을 확인한다. AI에 넘기는 입력은 해당 작업에 필요한 파일과 연결 자료를 포함한다. |
| 저장 표시                      | 변경이 화면에만 있는 상태, 복구 초안을 보관한 상태, 원본을 저장한 상태를 구분한다. 오류가 나면 현재 작업을 보존하고 실패한 저장의 재시도 방법을 표시한다.               |
| 외부 편집                      | 변경된 파일의 내용과 관련 캔버스 항목만 갱신한다. 편집 중인 동일 파일에 충돌이 생기면 로컬 초안과 외부 파일을 보존하고 사용자가 선택할 수 있게 한다.                    |

복구 초안은 강제 종료 후 되살릴 수 있는 작업 상태다. 원본은 프로젝트 폴더의 실제 파일로 외부 편집기와 AI가 읽는다. 30초 주기는 정상적으로 복구 초안이 기록될 때의 목표다. 갑자기 종료되면 마지막으로 성공한 초안 이후 작업은 유실될 수 있다.

## 0단계 · 읽기와 쓰기 기준선 측정

**완료.** 격리 Windows 환경에서 네 시나리오를 각각 3회 재현했다. 같은 시나리오를 1~3단계에서 비교할 수 있도록 입력 절차, 호출 횟수, 반영 지연과 원인을 기록했다. [0단계 측정 결과](../audits/2026-11-17-local-save-refresh-baseline.md)

- 문서가 여러 개 있고 그림과 HTML 결과가 섞인 합성 프로젝트를 사용한다. 짧은 메모 편집, 연속 펜 획, 펜 한 획 되돌리기, 외부 편집기의 단일 파일 변경을 같은 입력으로 재현한다.
- 작업별 전체 목록 조회 횟수, 변경 파일 읽기 횟수, 복구 초안·원본·히스토리 쓰기 횟수를 기록한다. 화면에 결과가 나타날 때까지의 지연과 파일 확정 완료까지의 지연을 각각 측정한다.
- **완료 기준**은 각 시나리오에서 전체 읽기나 쓰기를 일으킨 경로를 지목하고 이후 단계에서 같은 조건으로 비교할 수 있는 것이다.

## 1단계 · 저장 뒤 문서 전체 다시 읽기 제거

**완료.** 세 번의 비교 측정에서 메모 저장과 외부 메모 수정의 전체 목록 조회가 각각 0회였다. 외부 변경 중 다른 편집기·HTML 유지, 같은 문서의 충돌 보존, 구조 변경의 전체 갱신을 Windows 패키지에서 확인했다. [1단계 검증 결과](../audits/2026-11-17-local-save-refresh-stage1.md)

- 로컬 저장 응답으로 해당 문서나 그림을 화면에 반영한다. 파일 감시 이벤트가 같은 세션에서 확정한 파일과 일치하면 추가 화면 갱신을 생략한다. 외부 편집이나 AI 결과의 변경 경로를 확인할 수 있으면 기존 부분 갱신으로 전달한다.
- 프로젝트 첫 열기와 변경 범위를 확인하기 어려운 구조 변경에는 전체 갱신을 사용한다. 세션이 바뀌거나 같은 프로젝트를 다시 연 경우 이전 읽기 응답을 폐기한다.
- **완료 기준**은 Markdown 한 건 저장, 펜·도형·지우개 동작과 그림만 되돌리기에서 **전체 프로젝트 목록 재조회 0회**다. 외부 편집기가 수정한 문서 한 건은 새 본문이 표시되고 다른 파일의 열린 편집기와 HTML 실행 상태가 유지된다. 앱의 저장과 외부 변경이 겹칠 때에는 실제 외부 변경을 화면에 반영하거나 충돌로 표시한다.

## 2단계 · 복구 초안을 30초마다 묶기

**완료.** 고정 시계와 Windows 패키지에서 30초 주기, 강제 종료 후 복구, 구형 초안 처리와 폐기를 확인했다. 기준선과 같은 입력에서 펜 6획의 초안 쓰기는 23회에서 0회로 줄었다. [2단계 검증 결과](../audits/2026-11-22-local-save-refresh-stage2.md)

- 기존 편집기 초안 저장소와 문서 저장 큐를 사용한다. Markdown, 활성 펜·도형 작업, 캔버스 텍스트는 주기 동안 같은 대상의 최신 상태를 모아 보낸다. 진행 중인 제스처의 복구 초안에는 기존 복구 흐름에서 해석할 수 있는 작업 상태를 담는다.
- 저장 중 입력이 바뀌면 새 변경을 다음 기록 대상으로 남긴다. 기존 복구 데이터는 새 기록이 성공할 때까지 보존한다. 사용자가 초안을 명시적으로 버리면 폐기를 저장소에 반영해 재실행에서 다시 제시되는 일을 막는다.
- **완료 기준**은 저장 시계를 고정한 테스트에서 연속 편집의 첫 기록이 30초에 일어나고, 이후 내용이 바뀐 구간에만 추가 기록이 생기는 것이다. Windows 패키지를 기록 직전·직후에 강제로 종료하고, 재실행에서 마지막 성공한 초안과 기존 형식의 보관 초안을 열 수 있는지 확인한다.

## 3단계 · 원본은 2분 유휴에 저장하고 되돌리기는 작업 단위로 제공

**완료.** Windows 패키지에서 실제 2분 유휴 저장, 직접 저장, 정상 종료, 프로젝트 전환, AI 입력 준비와 작업별 Undo/Redo를 확인했다. 연속 펜 6획의 입력 구간에서 원본 쓰기는 6회에서 0회로 줄었고, 확정할 때 변경을 한 버전으로 저장했다. [3단계 검증 결과](../audits/2026-11-22-local-save-refresh-stage3.md)

- 기존 변경 큐에 대기 중인 작업을 모은다. 2분 유휴 또는 즉시 저장 시점에 해당 프로젝트 세션의 변경을 가져와, 마지막으로 확인한 원본과 현재 파일을 비교하고 기존 원자 쓰기 경로로 확정한다. 저장 중에 추가된 변경은 다음 저장에 포함한다.
- 화면은 미확정 작업을 포함해 표시한다. 완료한 펜 획·도형·지우개 동작은 원본 저장 전후 모두 개별적으로 되돌리고 다시 실행할 수 있다. 저장 대기 중인 획을 되돌렸다면, 이후 원본 저장에 그 획이 다시 포함되지 않아야 한다.
- 이름 변경, 휴지통, 복원처럼 파일 구조를 바꾸는 명령은 영향을 받는 대기 작업을 먼저 처리한 뒤 기존 명령 경로에서 확정한다. 복구 초안은 해당 변경의 원본 저장이 성공한 뒤 정리한다. 실패한 저장 때문에 프로젝트를 전환하거나 최신 파일이 필요한 AI 작업을 시작할 수 없으면 기존 문제 해결 흐름을 표시한다.
- **완료 기준**은 계속 작업하는 동안 2분 유휴 조건이 충족되기 전에는 자동 원본 쓰기가 발생하지 않고, 유휴 2분에 변경된 파일이 확정되는 것이다. `Ctrl+S`, 프로젝트 전환, 정상 종료, AI 실행 전에 각각 사용자가 본 최신 내용이 실제 원본에 반영되는지 확인한다. 펜 세 획을 그려 저장 전 한 획을 되돌리고 원본을 확정한 다음, 나머지 획의 되돌리기·다시 실행과 파일 내용을 검증한다.

**합의한 히스토리 정책**은 원본 저장 한 번당 디스크 히스토리 한 버전이다. 같은 그림 파일에 여러 획을 그렸다면 직전 원본과 이번 확정본의 변경 전후를 한 번 기록한다. 편집 세션에서는 획 단위로 되돌리고, 히스토리 화면에서는 저장 시점의 버전과 기존 디스크 기록을 조회·복원할 수 있다. 저장 실패 시 재시도와 복구가 작동하는 경계는 3·4단계에서 검증하고 관련 설계 문서에 반영한다.

## 4단계 · 실패·복구와 Windows 패키지 검증

**완료.** 일괄 저장 중 강제 종료와 외부 수정이 겹친 경우, 최신 초안과 외부 원본을 보존하고 재시도에서 히스토리 한 건을 확정하는 경로를 확인했다. [4단계 검증 결과](../audits/2026-11-22-local-save-refresh-stage4.md)

| 시나리오                                 | 통과 기준                                                                                                                              |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 저장 실패 후 같은 작업 재시도            | 마지막 원본과 복구 초안이 보존된다. 재시도 후 최종 내용과 기록이 한 번만 반영된다.                                                     |
| 외부 파일 수정과 원본 저장이 동시에 발생 | 외부 변경을 검출하고 최신 파일과 편집 초안을 둘 다 보존한다.                                                                           |
| 빠른 프로젝트 전환 또는 같은 경로 재열기 | 이전 세션의 타이머와 저장 응답이 열린 프로젝트나 화면 상태에 섞이지 않는다. 전환 전의 대기 작업은 마지막 저장 경계에서 처리한다.       |
| 정상 종료와 강제 종료                    | 정상 종료 후 최신 원본이 열린다. 강제 종료 후에는 마지막 성공한 복구 초안을 열 수 있다. 저장 실패 시 원본 저장 완료를 표시하지 않는다. |
| 기존 프로젝트를 새 패키지에서 열기       | 기존 파일·버전 히스토리·초안을 사용할 수 있고, 변경된 파일만 저장된다.                                                                 |

타입 검사, 아키텍처 경계 검사, 편집·저장 큐·프로젝트 세션 검사를 변경 범위에 맞춰 수행한다. 같은 Windows 패키지에서 `tests/drawing-undo-packaged.mjs`와 문서 저장·복구 시나리오를 검증한다. 최종 결과에는 기준선과 비교한 읽기·쓰기 횟수 및 화면 갱신 지연을 기록한다. 복구 유실이나 외부 변경 덮어쓰기가 재현되면 해당 주기의 적용을 보류하고 기존 저장 경로로 되돌린 뒤 보관된 초안의 복구를 확인한다. [회귀 검사 기준](../architecture/regression-matrix.md)
