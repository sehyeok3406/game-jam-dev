# 다중 선택 우클릭 일괄 처리와 다른 프로젝트로 복사

작성일: 2026-10-24. 현재 코드를 확인한 기획·구현 제안이며, 기능 구현 및 배포는 포함하지 않는다.

## 1. 목표와 확인한 문제

- 드래그·Shift·Ctrl 다중 선택 후 우클릭한 작업이 실제 선택 전체에 적용되게 한다.
- 선택한 자료를 다른 프로젝트의 지정 캔버스로 복사한다. 원본 자료는 유지한다.
- 한 항목만 바뀌거나, 이미지·HTML 관련 파일이 빠지거나, 선택한 자료가 중복 복사되는 일을 방지한다.

현재 `WorkspaceCanvas.tsx`는 문서·섹션·HTML별 단일 항목을 우클릭 메뉴 상태에 넣는다. `WorkspaceContextMenus.tsx`의 색상·삭제·캔버스 이동도 그 단일 항목을 사용한다. 다중 선택 자체는 존재하지만 메뉴의 명령 대상과 연결되지 않은 것이 확인된 직접 원인이다. 우클릭 과정의 선택 보존 여부는 실제 포인터 UI 검사로 추가 확인한다.

기존 `useCanvasClipboard.ts`와 `LocalCreationService.duplicate`는 현재 프로젝트의 문서 경로를 사용하는 복제 방식이다. 다른 프로젝트로 독립된 사본을 만드는 용도로 그대로 호출할 수 없다.

## 2. 선택과 우클릭 규칙

1. 선택된 항목 위에서 우클릭: 기존 전체 선택을 유지하고 전체를 명령 대상으로 고정한다.
2. 선택하지 않은 항목 위에서 우클릭: 기존 선택을 해제하고 우클릭한 항목 하나를 대상으로 한다.
3. 빈 공간 우클릭: 선택이 있으면 선택 메뉴와 빈 공간 작업을 구분해서 제공한다. 선택이 없으면 기존 생성·가져오기 메뉴를 표시한다.
4. 메뉴를 열 때 대상 ID·경로와 프로젝트/세션/캔버스를 고정한다. 실행 중 선택이 바뀌어도 다른 항목이 명령에 끼어들지 않는다.
5. 편집 내용을 저장한 후 최신 revision을 확인하되 ID가 바뀌거나 대상이 삭제되면 오류로 처리한다. 이름이 같은 다른 파일로 대체하지 않는다.
6. 프로젝트·캔버스 전환 시 이전 메뉴/대상 선택 창을 만료시킨다. 늦은 응답이 새 화면의 선택이나 알림을 변경하지 않게 한다.
7. 문서 본문과 캔버스 텍스트의 편집 중 우클릭, HTML 내부 우클릭은 기존 텍스트·미리보기 동작을 보존한다. 카드 외곽·헤더 및 선택 영역의 우클릭을 대상으로 연결한다. Alt 우클릭의 겹친 항목 선택도 유지한다.

다중 선택 메뉴 제목은 `5개 선택됨`처럼 표시한다. 기능별 실제 적용 수가 다르면 함께 표시한다. 색상이 섞여 있으면 특정 색을 전체 선택의 현재 색으로 표시하지 않는다.

## 3. 메뉴별 적용 정책

| 기능                                               | 제안 동작                                                                                                                                  |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 배경색                                             | 선택한 문서 카드·이미지 카드·HTML 카드 전체에 적용. 예: `배경색 · 카드 4개`. 섹션과 그림은 제외 개수를 표시하고 기존 색상 체계를 유지한다. |
| 삭제                                               | 선택한 문서·HTML·섹션·그림을 기존 혼합 삭제 확인 창으로 연결한다. 섹션 멤버와 개별 선택 문서는 중복 제거하고 실제 삭제 수를 안내한다.      |
| 다른 캔버스로 이동                                 | 기존 기능을 전체 선택에 연결한다. 프로젝트 안의 캔버스 이동과 프로젝트 간 복사를 문구로 구별한다.                                          |
| 최소화·펼치기                                      | 선택한 지원 항목에 같은 목표 상태를 적용한다. 하나라도 접혀 있으면 모두 펼치고, 아니면 모두 최소화하는 기존 선택 명령을 재사용한다.        |
| 다른 프로젝트로 복사…                              | 아래 복사 창을 연다. 단일 선택에서도 제공한다.                                                                                             |
| 히스토리·탐색기 열기·개별 폴더 분류·개별 섹션 관리 | 다중 선택 메뉴에서 단일 항목용 명령을 노출하지 않는다. 해당 항목만 선택했을 때 기존 상세 메뉴로 제공한다.                                  |

항목을 변경하는 일괄 작업은 대상 중 하나가 잠금·권한 문제로 불가능하면 실행 전에 막고 이유를 표시한다. 편집 가능한 항목만 조용히 일부 변경하지 않는다. 색상처럼 종류가 다른 항목을 제외하는 경우는 메뉴에서 적용/제외 개수를 먼저 표시한다.

색상 변경은 기존 `canvas:batch`에 `documents:set-color` 명령을 묶어 로컬·공동 모두 한 작업으로 기록하고 Undo 한 번으로 되돌린다. 최소화는 개인 표시 설정과 문서 저장이 섞인 기존 경로이므로 동일한 목표 상태를 적용하되, 모든 종류가 하나의 원자적 저장이나 히스토리가 된다고 가정하지 않는다.

## 4. 다른 프로젝트로 복사 사용자 흐름

`자료 다중 선택 → 우클릭 → 다른 프로젝트로 복사… → 대상 프로젝트 → 대상 캔버스 → 복사`

복사 창 구성:

- 제목: `다른 프로젝트로 복사`
- 요약: `메모 3 · 이미지 2 · HTML 1 · 섹션 1` 등. 섹션 내부 포함 수와 관련 파일 수는 별도 표기한다.
- 프로젝트 검색과 목록: 현재 프로젝트를 제외한 등록된 로컬·공동 프로젝트. 같은 이름은 종류·폴더 등으로 구별한다.
- 대상 프로젝트를 선택하면 캔버스 목록을 조회한다. 기본값은 대상 프로젝트의 첫 캔버스이며 다른 캔버스를 선택할 수 있다.
- 쓸 수 없는 공동 프로젝트, 휴지통·복구 중 프로젝트, 접근 불가능한 로컬 경로는 선택 불가와 이유를 표시한다. 공동 권한과 연결 상태는 실제 조회로 검증한다.
- 버튼: `취소`, `복사`. 실행 중에는 중복 실행을 막고 진행 상태를 표시한다.
- 성공: `프로젝트 B에 7개 항목을 복사했습니다`와 `대상 프로젝트 열기`를 제공한다. 자동 전환하지 않고 원본 선택을 유지한다.
- 실패: 이유와 재시도 경로를 표시한다. 저장 성공 후 화면 갱신 실패와 실제 저장 실패를 구분한다.
- 다른 복사 대상이 없으면 안내를 표시한다. 이 창 안에서 새 프로젝트를 만드는 기능은 이번 범위에 넣지 않는다.

첫 제공 범위는 데스크톱에서 시작하는 복사이며, 로컬↔로컬·로컬↔공동·공동↔공동을 목표로 한다. 공동 대상은 서버의 복사 가져오기 지원 여부를 확인하고, 미지원 서버에는 업데이트 필요 이유를 표시한다. 웹에서는 기존 다중 선택 버그를 함께 고치되, 프로젝트 간 복사 UI는 지원 capability가 있는 환경에만 표시한다.

## 5. 복사 데이터 규칙

| 대상                    | 복사 내용과 처리                                                                                                                          |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 메모·일반 문서          | 본문·제목·지원 metadata·색상·크기와 선택 묶음 내 상대 위치를 유지하고 새 ID를 부여한다.                                                   |
| 이미지 카드·본문 이미지 | 문서와 실제 이미지 파일을 함께 복사하고 참조 경로를 새 경로로 바꾼다. 같은 원본 파일은 한 요청에서 한 번만 복사한다.                      |
| HTML 결과               | HTML과 해당 결과의 CSS·JS·이미지 등 지원 보조 파일, 결과 관리 metadata를 새 결과 폴더로 복사한다. 관련 파일 누락 시 전체 요청을 거절한다. |
| 섹션                    | 섹션과 멤버 문서를 함께 복사하고 새 멤버 ID·경로로 다시 연결한다. 섹션과 멤버를 동시에 선택해도 멤버는 한 번만 복사한다.                  |
| 그림·캔버스 텍스트      | geometry·style·상대 위치를 유지하고 ID·generation·대상 canvasId를 새로 생성/지정한다.                                                     |
| 프로젝트 개요 문서      | 일반 사본 문서로 가져온다. 대상 `project.md`를 교체하지 않는다.                                                                           |

추가 기본 정책:

- 제목은 유지하고 파일 경로·결과 폴더 충돌은 자동으로 새 경로를 배정한다. 기존 파일을 덮어쓰지 않는다.
- 묶음의 상대 배치는 유지하며 대상 캔버스 기존 항목과 겹침을 줄이는 공통 위치 보정을 적용한다.
- 선택 묶음 내부 문서 링크·sources·결과 연결은 새 ID/경로로 바꾼다. 선택하지 않은 문서를 자동으로 따라 복사하지 않는다. 미포함 프로젝트 내부 참조는 사전 안내하고, 대상의 동명 자료로 잘못 연결되지 않도록 원본 출처 텍스트로 남긴다. 외부 URL은 유지한다.
- 대상에 없는 사용자 정의 상태는 이름이 같은 대상 상태에 연결하고, 없으면 대상 기본 상태로 지정하며 요약에 안내한다. 프로젝트 전체 상태/칸반 설정을 덮어쓰지 않는다.
- 실행 중 AI 작업·예약·실행 기록·잠금·인증 정보·프로젝트 설정·Undo 히스토리는 복사하지 않는다. AI 작업 문서는 일반 참고 문서로 가져오고 새 실행을 만들지 않는다.
- 칸반 보드와 게임 UI 같은 프로젝트 전역 도구는 자료 복사 대상에서 제외하고 개수를 알린다. 복사 가능한 자료가 하나도 없으면 실행하지 않는다.
- 프로젝트 안의 지원 경로만 읽고 심볼릭 링크·경로 탈출을 검사한다. 임의의 외부 파일을 재귀적으로 수집하지 않는다. 현재 파일 형식·용량·서버 제한을 유지하고, 제한 초과는 복사 전에 안내한다.
- 복사 원본에는 읽기 권한, 대상에는 쓰기 권한을 요구한다. 기존 편집용 `canEdit` 검사를 원본 읽기에 그대로 사용하지 않는다. AI가 쓰는 중인 관련 자료는 안정된 사본을 확보할 수 없으면 대기/재시도 안내로 처리한다.

## 6. 구현 순서와 코드 경계

### 1단계: 명령 대상과 다중 선택 메뉴 통일

- `src/ui/canvas/selection-plan.ts`와 `src/ui/workspace/workspace-types.ts`에 메뉴 명령 대상 모델을 정의한다. 문서·HTML·섹션·그림을 구분하고 중복 제거와 기능별 적용 가능 대상 계산을 순수 함수로 만든다.
- `WorkspaceCanvas.tsx`, `useCanvasSelection.ts`, 그림/텍스트의 `onContext`를 연결하여 선택 보존·선택 밖 우클릭·빈 공간 규칙을 구현한다. 이벤트 전파로 메뉴가 두 번 열리지 않게 한다.
- `WorkspaceContextMenus.tsx`에는 고정된 대상과 명령 콜백을 전달한다. 단일 항목 직접 IPC 호출을 제거하고 다중 메뉴의 기능·개수 표시를 구성한다.
- `CanvasSelectionActions`/`useSelectionActions`의 기존 flush·화면 수명·busy·권한 보호를 확장한다. 삭제·이동·표시 상태 변경은 기존 전용 서비스에 연결하고 동일한 대상 계산을 사용한다.
- 이 단계에서 색상·삭제·캔버스 이동·최소화의 다중 선택 동작을 먼저 완성하고 회귀를 확인한다.

### 2단계: 프로젝트 간 복사 계획과 서비스

- 새 프로젝트 복사 계약을 `src/contracts`에 정의한다. 요청에는 원본 세션 참조·대상 프로젝트 ID·대상 캔버스 ID·선택 ID/경로·requestId를 넣는다. renderer가 임의의 디스크 root를 지정하지 못하게 한다.
- application의 별도 `ProjectCopyService`를 두고 `선택 정규화 → 원본 저장 완료 → 일관된 사본 읽기 → 의존 파일 수집 → ID/경로 변환 → 대상 검증 → 게시`를 소유하게 한다. 현재 프로젝트를 대상 프로젝트로 전환해서 쓰는 우회 구현은 하지 않는다.
- 핵심 복사 계획은 순수 데이터로 계산한다. 파일/문서/섹션/결과/그림의 ID·경로 변환표를 한 번 만들고 모든 참조에 공통 사용한다.
- 프로젝트 목록은 기존 `listProjects`를 재사용한다. 비활성 대상의 캔버스 조회·권한 확인·가져오기를 별도 프로젝트 핸들로 연결한다.
- 로컬 대상은 대상 root에 고정된 repository·publisher·history를 사용한다. 관련 바이너리와 metadata의 준비·실패 복구까지 검증하고 한 복사 작업으로 기록한다.
- 공동 대상은 인증된 별도 client와 서버 가져오기 명령으로 처리한다. 임의 snapshot 덮어쓰기를 허용하지 않고 지원 형식·용량·대상 revision·역할·lifecycle·잠금을 서버에서 검사한다. 기존 `files:import-batch`만으로 섹션/그림/HTML 전체를 처리할 수 있다고 가정하지 않는다.
- 서버 명령을 추가하면 `contracts/commands.ts`, reducer, access policy, persistence/history/receipt, capability 안내와 관련 검증을 함께 연결한다.

### 3단계: 복사 창과 완료 동작

- `ProjectCopyDialog`와 전용 hook으로 대상 검색·캔버스 조회·요약·실행·실패 상태를 분리한다. `WorkspaceScreen.tsx`에는 조립과 콜백만 추가한다.
- 실행 직전에 대상 권한/캔버스/lifecycle을 재검사한다. 창이 열린 사이의 삭제·권한 변경·접속 해제를 반영한다.
- 원본 읽기는 일관된 사본으로 고정하고, 쓰기는 대상 한 곳에서 한 작업으로 완료한다. 게시 전 실패에는 생성한 파일이 남지 않도록 한다.
- requestId로 중복 클릭·응답 유실 후 재시도가 중복 사본을 만들지 않게 한다. 이미 저장된 작업은 화면 전환 때문에 취소됐다고 표시하지 않는다.
- 대상 프로젝트에서 Undo 한 번으로 이번 복사 항목 전체를 제거하고 Redo로 복원한다. 원본 히스토리에 복사 생성 기록을 넣지 않는다. 단, 복사 전 기존 편집 내용 저장은 원본의 정상 저장 이력으로 남을 수 있다.

## 7. 검증과 완료 기준

1. 드래그·Shift·Ctrl 선택 각각에서 선택 안/밖/빈 공간 우클릭 대상을 실제 UI로 확인한다. 텍스트 편집과 Alt 겹침 메뉴 회귀도 검사한다.
2. 문서 여러 개·문서+HTML의 색상 일괄 변경, 혼합 색상 표시, 적용 대상 개수, 한 번의 Undo/Redo를 확인한다.
3. 혼합 삭제·캔버스 이동·최소화, 섹션과 멤버 중복 선택, 잠긴 대상 포함, 선택/화면 변경 중 응답을 검사한다.
4. 네 가지 로컬/공동 복사 조합에서 문서·이미지·HTML 보조 파일·섹션·그림의 배치와 참조를 확인한다. 원본의 복사 전후 내용은 동일해야 한다.
5. 원본 프로젝트를 닫거나 원본 자료를 제거해도 대상 이미지·HTML이 유지되는지 확인한다. 원본 제거는 검사 전용 임시 프로젝트에서 수행한다.
6. 대상의 동명 파일·같은 문서 ID·같은 결과 폴더, 상태 미일치, 누락 파일·용량 초과·경로 탈출·잘못된 참조를 검사한다.
7. 로컬 저장 중 실패와 공동 서버 반영 실패, 응답 유실·동일 requestId 재시도, 대상 권한 변경·삭제·구버전 서버에서 부분 사본이나 중복 생성이 없는지 검사한다.
8. 대상 Undo/Redo와 앱 재시작 후 복사본 유지, 원본 화면의 선택 보존을 확인한다.

기존 `selection-actions.test.mjs`, `selection-hooks.test.mjs`, `selection-ui-scenarios.mjs`를 확장하고 복사 계획/서비스·서버 가져오기 검사를 추가한다. 실제 Windows 패키지에서는 임시 프로젝트와 테스트 서버로 핵심 흐름을 검증한다.

타입 검사·린트·독립 자동 검사는 병렬 실행 가능하다. 같은 출력 폴더를 쓰는 빌드·UI·패키지 검사는 순서대로 실행한다. 배포 요청이 이어지면 저장소 `AGENTS.md`와 `UPDATES.md`의 게시 절차를 따른다.

## 8. 권장 작업 구분

- 작업 A: 선택 대상 통일과 기존 우클릭 명령의 다중 적용 수정.
- 작업 B: 자료·파일·참조를 포함하는 프로젝트 복사 서비스와 로컬/공동 저장 경로.
- 작업 C: 복사 창 연결, UI/패키지 검증, 사용 문구 정리.

각 작업을 검증 가능한 단위로 나누되, 프로젝트 간 복사 완료는 관련 파일의 독립성·실패 복구·대상 Undo까지 충족했을 때 인정한다.
