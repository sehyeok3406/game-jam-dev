# 문서·HTML 카드 표시 통일 구현 계획

작성일: 2026-10-31. 상태: 사용자 승인에 따른 1~5단계 구현·검증 완료. 표시 제목·실제 파일명 불일치를 추가 점검 항목으로 기록했다. 커밋·푸시·배포는 마지막 지시까지 보류한다.

## 목표와 범위

캔버스에서 카드의 첫 줄만 보아도 자료 이름을 식별하고, 유형·상태·기록은 속성에서 확인하도록 한다. MD·HTML을 우선 통일하고 같은 DocumentCard를 사용하는 이미지·AI 작업 문서의 표시도 확인한다. 게임 화면 내부의 디자인이나 새로운 문서 관리 기능은 이번 범위에 포함하지 않는다.

명시된 요청은 상단 이름 표시, 문서 유형의 속성 이동, 제목 색상 기능 비활성화다. 추가 점검에서 확인한 중복 제목·속성 혼재·상단 과밀·중복 상세 정보·색상 의미·중복 닫기는 함께 정리할 대상으로 계획한다.

## 표시 규칙

### 1. 카드 상단은 자료 이름

- MD의 기존 유형 라벨 자리에 문서 제목을 표시한다. HTML도 표시 제목을 우선 사용하고 없으면 기존 파일명 대체값을 사용한다. MD 표시 이름 변경과 실제 파일명 변경을 혼동하지 않는다.
- 두 카드의 제목 글꼴·굵기·중립 배경·여백을 맞춘다. 긴 제목은 한 줄 말줄임과 전체 제목 툴팁을 제공하고, 조작 버튼 때문에 제목 영역이 사라지지 않도록 한다.
- 펼침·접힘 모두 동일한 이름과 위치를 유지한다. MD 본문 위의 별도 큰 제목 띠는 상단으로 통합한다.
- 상단 제목을 눌러 기존 제목 편집을 시작한다. 헤더의 나머지 영역은 드래그에 사용한다. 제목 입력 중에는 드래그·캔버스 단축키가 개입하지 않도록 한다.
- HTML 실행·작업 중·경고 표시는 이름과 구분된 보조 정보로 표시한다. 기능별로 필요한 실행 버튼은 유지한다.

### 2. 유형과 상태는 속성

- 속성 영역에 문서 유형을 독립 행으로 표시한다. 현재의 `미정 사항 · 초안`처럼 유형과 상태를 한 값으로 합치지 않는다.
- 파일별 작업 상태, 생성자·생성일·마지막 편집자·편집일을 같은 속성 묶음에서 확인한다. 기존 상태 적용·칸반 포함·개인 표시 설정의 저장 의미를 유지한다.
- MD에는 기존 문서 유형을, HTML에는 HTML 자료임을 확인할 수 있는 유형을 표시한다. 이미지·AI 작업도 기존 유형을 보존한다.
- 파일 경로·ID·좌표·크기는 별도의 상세 정보 묶음으로 둔다. 문서 유형과 생성 기록은 그 묶음에 중복 표시하지 않는다.
- 상단에는 이름과 간결한 상태 표시를 우선 배치한다. 생성자·날짜는 속성에서 확인하고 기존 개인 표시 설정은 삭제하지 않고 보관한다. 상태를 표시하지 않도록 한 개인 설정은 존중한다.
- 기존 상태 전환 서비스·권한·충돌 검사·개인 설정 경로를 재사용한다. 문서 유형 이동을 위해 파일 형식이나 협업 프로토콜을 바꾸지 않는다.

### 3. 제목 중복은 표시 단계에서 처리

- 상단으로 이동한 카드 제목과 본문 첫 H1이 같으면 읽기 화면에서는 첫 H1의 중복 표시를 생략한다.
- 안전한 비교 대상은 본문의 첫 블록인 일반 텍스트 H1으로 한정한다. 다른 제목, 본문 중간 제목, 링크·이미지·별도 의미가 포함된 제목은 유지한다.
- 원본 Markdown을 수정하거나 제목을 자동 삭제하지 않는다. 편집·소스 보기에서는 원문을 그대로 제공한다. HTML 내부의 제목은 실행 콘텐츠이므로 이 규칙을 적용하지 않는다.
- 검색이 새 상단 제목을 찾고 중복 제목을 불필요하게 두 번 집계하지 않도록 함께 확인한다. 숨긴 제목이 있는 읽기 화면을 눌렀을 때 본문 편집 위치가 어긋나지 않아야 한다.

### 4. 색상은 역할을 줄이고 데이터는 보존

- 제목·카드 색상 변경 UI는 단일 MD, HTML, 다중 선택 메뉴에서 모두 비활성화하고 사용 중지 이유를 표시한다. 제목 글자색 편집기나 게임 UI 요소의 색상 설정과 혼동하지 않는다.
- 카드 헤더는 라이트·다크 테마의 공통 기본색을 사용한다. 기존 카드 배경색과 유형별 장식색도 본문 가독성을 해치지 않는 중립 표시로 정리한다.
- 상태·경고·선택·잠금처럼 동작이나 상태를 설명하는 색상은 구분하여 유지한다.
- 기존 `backgroundColor` 저장값과 읽기·저장 API는 보존한다. 기능의 영구 삭제와 데이터 정리는 별도 결정으로 남긴다.

### 5. 중복 조작 정리

- 일반 문서의 상세 정보 진입은 카드 헤더의 정보 버튼으로 통일한다. 하단의 동일한 상세 정보 버튼은 제거한다. AI 작업 복사·이미지 설명 편집 등 고유 동작은 유지한다.
- 우측 패널을 닫는 X는 패널 상단으로 통일한다. 내부 상세 보기에서 돌아가는 동작이 필요하면 뒤로가기 역할로 구분하여 패널 닫기와 의미를 분리한다.
- 도킹 패널과 독립 상세 정보 표시 경로가 같은 표시 규칙을 사용하도록 함께 수정한다.

## 구현 순서와 담당 파일

### 추가 점검: 표시 제목과 실제 파일명 불일치 (개인 Markdown 1~2단계 구현)

- 사용자는 캔버스 제목과 실제 파일명을 통일하는 방향을 선택했다. 현재 MD는 frontmatter `title`을 우선 표시하며 제목 편집은 파일명을 바꾸지 않는다.
- 이름 확정 시 실제 파일명과 참조를 함께 갱신하고, 기존 불일치는 현재 표시 제목을 기준으로 미리보기 후 정리하는 [후속 구현 계획](2026-10-31-unified-file-names.md)을 작성했다. HTML의 고정 실행 경로, v1 문서, 저장 큐·협업·복구도 포함한다.
- 2026-11-01에 개인 Markdown의 명시적 이름 확정·실제 개명·참조/복구를 구현하고 검증했다. HTML·일괄 정리·협업/오프라인·생성 경로 통합은 후속 범위로 남긴다. 기존 표시 통일 1~5단계와 이름 통일의 단계 번호를 구분한다.

## 완료 기준과 검증

- 같은 캔버스의 MD·HTML·이미지·AI 작업 문서를 비교한다. 펼침·접힘·선택·편집·잠금·저장 실패 상태에서도 이름·유형·상태를 구별할 수 있어야 한다.
- 짧은 이름·긴 한글 이름, 기본·최소 지원 창과 좁은 카드, 두 테마에서 제목·속성·조작 버튼이 겹치지 않아야 한다. hover 없이도 키보드로 제목 편집·속성 열기·닫기가 가능해야 한다.
- 제목 변경·본문 편집·체크박스·한글 조합·초안 복구·저장 재시도·Undo/Redo·프로젝트 재열기를 확인한다. 원본 Markdown과 파일 경로·ID·기존 색상 값의 보존을 확인한다.
- 중복 H1의 일치·불일치·다른 위치·링크/이미지 포함·빈 본문을 확인한다. 검색 건수와 편집 커서 위치도 검사한다.
- 단일 MD·HTML·혼합 선택에서 색상 변경이 실행되지 않아야 한다. 다른 그림·텍스트·게임 UI의 색상 기능은 기존대로 동작해야 한다.
- 기존 속성/상태와 편집 회귀 검사에 연결한다: `tests/file-properties.test.mjs`, `tests/presentation-ui-scenarios.mjs`, `npm run test:autosave:ui`, 문서 링크·검색 관련 검사. 실제 캔버스 UI에 표시 통일 검사를 추가하고 최종 Windows 패키지의 저장·재시작도 검증한다.
- TypeScript 변경 후 `npm run typecheck`, 린트·서식 검사를 수행한다. 의존 경계 변경 시 `npm run test:architecture`를 수행하며 같은 소스에서 통과한 검사는 불필요하게 반복하지 않는다.

## 적용과 보고

코드 구현은 사용자의 시작 지시 이후 수행한다. 완료 시 확정 요청과 추가 정리 항목의 적용 결과, 실제 화면 비교, 검증 결과와 남은 제한을 보고한다. 커밋·푸시·배포는 별도 지시 범위에 따라 진행한다.

## 1단계 구현 기록

- MD의 유형 라벨 자리를 이름으로 바꾸고 큰 제목 띠를 없앴다. 편집 중 이름 입력란도 같은 헤더에 둔다. 유형 자체와 기존 상세 정보는 보존하며 속성 재배치는 2단계에서 수행한다.
- HTML은 표시 제목을 우선 사용하고 없으면 실제 파일명으로 표시한다. 실행 상태는 이름과 구분한다. MD·HTML은 공통 13px 제목 서식과 38px 기본 헤더를 사용하며 긴 이름은 말줄임·툴팁을 제공한다.
- 펼친 MD의 제목 클릭·Enter/Space로 기존 편집 세션을 시작한다. Ctrl+S, Ctrl+Enter, Escape와 한글 조합, 기존 저장 큐·초안 경로를 유지한다. 나머지 헤더로 드래그하고 접힘 상태에서도 이름을 표시한다.
- 좁은 카드에서는 기존 개인 설정을 바꾸지 않고 헤더 속성 배지를 시각적으로 접어 제목과 조작 공간을 확보한다. 색상 기능, 속성 구조, 본문의 같은 제목, 상세 정보/닫기 버튼 정리는 아직 변경하지 않았다.
- 제목이 버튼으로 이동해도 검색되도록 명시적으로 검색하는 루트 버튼의 텍스트를 허용했다. 본문 안의 조작 버튼과 숨겨진 텍스트는 계속 검색에서 제외한다.
- `node tests/run-card-headers-ui.mjs`: 실제 포인터·키보드 제목 편집과 저장, MD/HTML 드래그, iframe 유지, 접기·펼치기, MD 260px·HTML 420px 크기, 두 테마와 제목 검색을 확인한다. 화면 증거는 `out/card-headers-ui`에 보존한다.
- 저장 회귀 검사는 격리 디렉터리에서 실제 HTTP/SSE 서버·상대 클라이언트·저장 지연·잠금 heartbeat를 사용한다. `GC_SAVE_TEST_DIRECTORY`로 반복 검사 자료를 분리할 수 있게 했으며 기존 기본 경로는 유지한다. 최종 패키지 검증은 나머지 단계 통합 후 수행한다.
- 검증 결과: 타입·린트·서식, 아키텍처 10개, 검색·문서 저장·파일 속성 회귀 29개, 실제 카드 헤더 UI를 통과했다. 격리된 서버 저장 검사에서 제목·본문·원문·집중 편집의 연속 입력과 지연된 저장 응답 후 DOM·포커스·커서 유지, 잠금 해제 중 추가 입력 저장, 상대 클라이언트의 최종 내용 일치를 확인했다. 변경 전 화면도 같은 격리 환경에서 비교했다.

## 2~3단계 구현 기록

- MD·HTML의 유형, 문서 단계/AI 작업 상태, 상태 속성과 생성·편집 기록을 속성 묶음으로 통합했다. 유형과 단계를 하나의 값으로 합치지 않으며 파일 경로·ID·좌표는 아래 파일 정보 묶음으로 옮겼다. 도킹·독립 상세 정보 경로에 같은 규칙을 적용한다.
- AI 작업 문서에는 작업 상태와 기록을 표시하고 일반 문서의 칸반 상태 조작을 새로 노출하지 않는다. 이미지 등 기존 유형은 유지한다. 문서 단계는 기존 문서 metadata의 상태이며 칸반 상태와 구분한다.
- 상단 배지는 기존 개인 설정을 따르는 상태만 표시한다. 생성자·날짜와 더보기 배지를 제거하고 기존 개인 표시 플래그를 삭제하지 않는다. 속성의 기록 행은 읽기 전용이며 상태 적용·값·상단 표시·관리 명령은 기존 저장·권한 경로를 재사용한다.
- 문서 이름과 일치하는 첫 일반 텍스트 H1만 읽기 AST에서 생략한다. 다른 제목·중간 제목·H2·서식·링크·이미지·코드 제목은 보존한다. 원본 본문을 자르거나 다시 저장하지 않으며 편집·원문 보기에는 H1을 그대로 제공한다. HTML 실행 콘텐츠와 제목을 전달하지 않는 다른 Markdown 읽기 화면은 변경하지 않는다.
- 생략 이후 블록의 원래 인덱스·소스 위치를 읽기 DOM에 연결한다. 본문 클릭은 편집기에서 같은 원래 블록으로 이동하며 체크박스의 Markdown 소스 offset은 유지한다. 읽기 검색은 상단 이름을 한 번 찾는다.
- `tests/markdown-title.test.mjs`의 변환·보존·줄바꿈·한글 정규화·체크박스 위치 검사와 `tests/card-properties-ui-scenarios.mjs`의 실제 속성 조작·개인 설정 보존·원문/편집·문단 커서·체크박스 검사를 추가했다.
- 전체 자동 검사 1,058개(실패·skip 0), 타입·린트·서식과 실제 카드 UI를 통과했다. 실제 HTTP/SSE 서버의 제목·본문·원문·집중 편집 연속 입력, 지연 저장 후 포커스·커서 유지 및 상대 클라이언트 수렴도 통과했다. 아키텍처 검사를 포함하며 FileProperties의 해소된 shared 호환 import 예외 1건을 줄였다. 새 예외는 없다.
- 당시 색상 비활성화와 중복 상세 정보/닫기 정리는 4~5단계에 남겼다. 검사 기록은 `out/card-properties-*.log`, 화면 증거는 `out/card-headers-ui`에 보존한다.

## 4~5단계 구현 기록

- MD·HTML·다중 선택 메뉴의 색상 팔레트를 비활성 버튼과 중지 사유로 교체했다. UI의 저장 명령 연결을 제거했으며 기존 `backgroundColor` 데이터, 저장 API와 실행 취소 서비스는 보존한다. 일반 텍스트·그림·게임 UI 요소의 색상 조작은 변경하지 않았다.
- 카드의 기존 사용자 배경색과 유형별 장식 배경·테두리를 중립 표시로 정리했다. HTML 헤더도 같은 기본색을 사용한다. 미니맵은 저장된 사용자 색상 대신 기존 항목 종류별 표시를 사용하며 그림 색상·선택 표시와 상태·경고·잠금 색상은 유지한다.
- 일반 MD·이미지 카드 하단의 중복 상세 정보 버튼을 제거했다. 헤더 정보 버튼, AI 작업 복사와 이미지의 설명 편집·에셋 동작은 유지한다.
- 도킹 패널의 상단 X는 전체 패널 닫기로 유지했다. 상세 정보 내부의 X를 `뒤로`로 바꾸고 속성 탭으로 포커스를 돌린다. 독립 상세 정보의 단일 닫기는 유지한다. Esc 닫기와 최초 정보 버튼으로의 포커스 복귀를 확인했다.
- 실제 카드 UI에서 단일 MD·HTML 및 포인터/Shift를 사용한 다중 선택 메뉴, 비활성 버튼 클릭 후 색상·히스토리 불변, 두 테마의 중립 배경, 미니맵, 상세 정보 단일 진입과 뒤로/닫기/Esc/포커스를 검증했다. 이전 단계의 제목 편집·드래그·크기·검색·속성·본문 위치 검사도 함께 통과했다.
- 최종 소스의 전체 자동 검사 1,058개(실패·skip 0), 타입, 아키텍처 10개와 실제 카드 UI가 통과했다. 린트·서식도 확인하며 기존 Discord mock의 `no-this-alias` 경고는 남아 있다.
- `npm run package`로 Windows 패키지를 한 번 빌드했다. `node tests/card-appearance-packaged.mjs`에서 실제 패키지의 상단 이름·속성·중복 H1·색상 차단·히스토리, 포인터/키보드 제목 저장과 전체 프로세스 재시작을 검증했다. 기존 색상·사용자 정의 frontmatter·Markdown 원문·HTML 파일은 보존됐다. 화면 증거는 `out/card-appearance-packaged`에 보존한다.
- 검사 기록은 `out/card-appearance-*.log`다. 설치 파일 제작·커밋·푸시·배포는 수행하지 않았다.
