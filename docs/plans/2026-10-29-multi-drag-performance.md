# 다중 항목 드래그 성능 개선 구현 계획

작성일: 2026-10-29. 상태: 구현·로컬 검증 완료, v0.38.4 게시 준비.

## 목표와 범위

다중 선택 이동에서 좌표 변경이 문서 본문과 관계없는 화면의 반복 렌더로 이어지는 비용을 줄인다. 사용자는 드래그 중 부드럽게 위치를 확인하고, 놓으면 기존 경로로 최종 위치를 저장한다.

사용자 결정에 따라 이동 중 위치 저장, 5초 주기 저장, 복구용 위치 초안은 모두 제외한다. 저장 타이머·새 저장소·새 IPC·협업 프로토콜을 추가하지 않는다. 배포는 이 계획의 범위가 아니다.

## 조사 근거와 책임 배치

- 현재 `WorkspaceCanvas.onNodeDragStop` → `useCanvasGeometry.persistDraggedNodes`가 저장 진입점이다. 문서·섹션은 `layouts:update`, 문서와 그림의 혼합은 기존 `canvas:batch`를 사용한다.
- 현 작업 사본의 Electron fixture에서 문서 60개 이동 중 본문 렌더 780회, 저장 호출 0회를 관측했다. data/selected가 같은 본문 실행을 생략한 메모리 변환 실험에서는 본문 렌더 0회였다. 이 수치는 단일 개발 환경 실험이며 배포 성능 보장은 아니다.
- UI의 `ui/canvas`, `ui/documents`, `ui/preview` 및 해당 화면용 features가 렌더·입력·임시 geometry를 소유한다. runtime → application → adapter/server의 기존 저장·권한·히스토리 책임을 재사용한다.
- `contracts`/`core` 변경은 계획하지 않는다. 기존 `pendingGeometry` sequence와 프로젝트/화면 수명을 유지한다. 새 코드에서 `src/shared.ts`를 import하지 않는다.
- 기존 미커밋 변경이 있는 `WorkspaceCanvas`, `DocumentMarkdown`, 게임 UI·패널 등의 코드는 현재 변경 내용을 기준으로 최소 수정하고 덮어쓰지 않는다.

## 1. 비교 기준과 회귀 시나리오 준비

조사용 `out/drag-investigation` 실험을 재사용하되, 유지할 검사는 테스트 영역으로 옮긴다. 제품 코드에 전역 카운터나 계측용 저장 경로를 넣지 않는다.

- 문서 20/100/300개와 긴 Markdown·표·본문 이미지 fixture를 준비한다.
- 실제 포인터 입력을 사용해 단일/다중/섹션 이동과 혼합 선택을 검사한다. 테스트에서 전체 선택과 실제 최종 좌표 변화도 확인해 드래그되지 않은 결과를 성공으로 인정하지 않는다.
- 시작·선택·드롭의 정당한 갱신과 이동 중 좌표만 변하는 구간을 구분해 본문 실행을 계측한다.
- 이동 중 저장 0회, 일반 문서·섹션 드롭당 배치 1회와 최종 좌표를 단언한다. 5초를 넘겨 유지해도 위치 저장이 없어야 한다.
- 성능 비교는 같은 fixture/창 크기/빌드/입력에서 충분한 이동 구간을 확보해 최소 3회 측정한다. renderer trace 또는 입력→화면 반영 지연, 프레임 간격, 본문 렌더 횟수를 기록한다. 처리된 입력/프레임 표본 수가 다른 총합만으로 속도 배수를 계산하지 않는다.

## 2. 좌표 갱신과 카드 내용 렌더 분리

주요 대상: `DocumentCard.tsx`, 필요 시 `DocumentMarkdown.tsx`, `CanvasItemResizer.tsx`, 각 노드 컴포넌트.

- React Flow 노드 진입점에서 실제 내용 컴포넌트에 필요한 props만 전달한다. 문서 카드의 내부 컴포넌트는 data/selected 등 실제 사용하는 입력으로 메모이제이션한다. 사용하지 않는 position/dragging props 때문에 Markdown을 다시 계산하지 않게 한다.
- 기존 문서 편집 hook과 DOM 수명을 보존한다. 제목/본문·체크리스트·이미지·문서 링크·잠금·저장 상태·선택 변경 및 내부 state/context 변경은 정상 반영한다. 편집기를 드래그 때 마운트 해제하거나 내용 갱신을 통째로 막지 않는다.
- 변경되는 함수 props를 비교에서 임의로 무시하지 않는다. 불필요하게 새로 생기는 콜백/Context 값만 안정화한다. `CanvasResizeProvider`는 save/scope가 같으면 value를 재사용한다.
- `SectionCard`, `PreviewCard`, `GameUiNode`, `KanbanNode`, `DrawingNode`와 `TextDrawingNode`의 입력을 점검한다. 기존 `memo`의 존재만으로 최적화됐다고 판단하지 않으며 전체 NodeProps 전달로 다시 실행되는 내부 내용은 좁은 props 경계로 분리한다.
- 노드별 gesture·zoom·resizer·텍스트 편집·iframe의 실제 의존성을 먼저 확인한다. 크기/좌표에 의존하는 도구는 필요한 갱신을 유지한다. 모든 노드에 동일 비교 함수를 일괄 적용하지 않는다.

완료 기준: 내용·선택·권한 등 다른 입력이 같은 순수 위치 이동 구간에서 문서 본문 렌더 0회. 실제 본문/권한/선택 변경은 드래그 중에도 반영된다.

## 3. 상위 화면의 불필요한 작업 축소

주요 대상: `WorkspaceScreen.tsx`, `WorkspaceCanvas.tsx`, `useCanvasSelection.ts`, 필요 시 `useCanvasNodes.ts`와 패널 경계.

- 선택에 따른 문서/그림/미리보기 계산과 패널 props가 좌표만 바뀔 때 새 값이 되지 않도록 선택 상태의 변경 경계를 정리한다. 전체 nodes를 의존성에 둔 useMemo만 추가하는 방식은 해결로 간주하지 않는다.
- 카드·패널에 전달되는 불필요한 새 객체/배열/함수와 다중 드래그 중 반복되는 빈 가이드 상태 갱신을 줄인다. 기존에 안정화된 문서 링크 콜백 등은 재구현하지 않는다.
- 우선 기존 상태 모델과 React Flow store/API를 활용해 측정된 비용을 제거한다. 이후에도 상위 화면 렌더가 지배적이면 노드 상태를 캔버스 가까이 격리하는 최소 변경을 적용한다. 이때 전체 선택·새 항목 선택·컨텍스트 메뉴·클립보드·키보드 명령이 최신 노드를 읽는지 함께 검사한다. 별도 전역 node store를 만들지 않는다.
- 포인터 이동을 긴 간격으로 throttle하거나 카드를 숨기는 방식은 기본 해법으로 사용하지 않는다.

완료 기준: 좌표 변경만으로 관계없는 패널/내용이 반복 렌더되지 않고, 동일 입력의 100/300개 비교에서 지연과 긴 프레임의 분포가 개선된다. 미달 시 trace로 남은 병목을 확인한 뒤 범위를 좁혀 수정한다. 테스트 환경의 절대 FPS를 제품 보장으로 제시하지 않는다.

## 4. 드롭 후 갱신 정리와 기존 저장 보존

주요 대상: `useCanvasGeometry.ts`, `usePreviewWindows.ts`.

- 문서·섹션의 `layouts:update`, 그림 혼합의 `canvas:batch`, 게임 UI의 기존 명령/큐, 칸반 개인 설정 경로를 유지한다. 게임 UI 저장을 무조건 Promise.all로 바꾸지 않는다.
- HTML 미리보기 여러 개의 geometry를 먼저 수집하고 기존 `updatePreviewWindows`를 활용해 상태 갱신을 합친다. 단일 helper와 다중 helper의 실패 표시/성공한 대상 반영 차이를 검토하고, 실패가 중복 표시되거나 저장 성공으로 처리되지 않게 한다.
- 미리보기 설정은 기존 개인 설정이다. 문서와 묶인 원자적 저장/Undo로 바뀌었다고 간주하지 않는다. 성공한 저장을 이후 화면 reload 실패 때문에 다시 쓰지 않는다.
- 부모 섹션 이동 시 자식 중복 반영 제외, 상대/절대 좌표, 접힌 높이, 스냅 최종 위치와 섹션 소속 확인 시점을 유지한다.
- 저장 중 새 드래그가 시작돼도 이전 완료가 최신 pending geometry를 지우지 않아야 한다. 실패·충돌·잠금·프로젝트 A→B→A와 캔버스 전환 후 늦은 결과를 기존 session/sequence 경계로 격리한다.

## 검증과 완료 조건

| 검증           | 실행/확인 범위                                                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 정적 검사      | `npm run typecheck`, `npm run lint`; 파일/의존/runtime 경계 변경 시 `npm run test:architecture`. 독립 검사는 병렬 실행                                              |
| 기존 단위 회귀 | `node --test tests/workspace-commands.test.mjs tests/workspace-data.test.mjs`; 수정한 노드 종류의 기존 테스트와 새 렌더/드래그 회귀 추가                            |
| 실제 화면      | `npm run test:canvas-selection:ui`, `npm run test:autosave:ui`; 링크/그림/게임 UI/섹션을 수정한 경우 해당 기존 UI 검사 선택                                         |
| 실제 패키지    | 동일 소스를 한 번 package한 결과물로 포인터 다중 드래그·최종 파일 좌표·metadata/본문 보존·Undo/Redo·완전 재시작 후 위치 보존 검사. 기존 packaged runner 패턴 재사용 |
| 협업/오류      | 임시 서버/프로필에서 권한/잠금·외부 변경 충돌·응답 지연·다시 드래그/프로젝트 전환 확인. 실제 사용자 데이터나 운영 서버 미사용                                       |
| 성능 비교      | 이동 중과 드롭 후 저장 시간을 따로 기록. 동일 조건 여러 실행의 지연·긴 프레임·렌더 횟수를 전후 비교                                                                 |

문서·섹션만의 다중 이동은 기존처럼 한 배치 명령과 한 Undo 단위를 보존한다. 모든 혼합 항목이 한 히스토리/원자적 저장으로 바뀐다고 주장하지 않는다. 저장 API 한 번과 파일 쓰기 한 번도 구분한다.

이미 같은 소스에서 통과한 검사는 반복하지 않는다. 미커밋 작업의 기존 실패와 이번 변경의 회귀는 근거로 구분하며, 검사 예외를 늘리거나 규칙을 완화하지 않는다. `contracts`/`core`를 실제로 수정하게 되면 해당 strict typecheck도 추가한다.

렌더 소유권/경계가 바뀌는 부분은 `docs/architecture/r05-workspace.md`에, 유지할 회귀는 `regression-matrix.md`에 반영한다. 현재 계획대로 저장 정책·공개 계약을 유지하면 별도 ADR은 필요하지 않다.

## 산출물

- 카드 내용과 좌표 갱신을 분리한 제품 코드 및 상위 갱신 최적화.
- HTML 다중 이동의 기존 일괄 helper 연결과 실패/세션 회귀.
- 유지 가능한 렌더·다중 드래그 회귀, 실제 패키지 저장 검증 결과, 전후 성능 기록.
- 관련 현재 설계 문서 갱신과 남은 제약을 포함한 완료 보고.

이 문서는 계획이며, 제품 변경·추가 검사·패키지 검증을 완료했다는 뜻이 아니다.
