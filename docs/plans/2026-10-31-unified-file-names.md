# 캔버스 제목·실제 파일명 통일 구현 계획

작성일: 2026-10-31. 갱신: 2026-11-01. 상태: 1~2단계의 이름 규칙·개별 개인 Markdown 개명·참조/복구 구현 및 검증 완료. HTML 실행 파일, 기존 문서 일괄 정리, 협업·오프라인과 생성 경로 연결은 후속 단계다. 커밋·푸시·배포는 마지막 지시까지 보류한다.

## 목표와 확정할 동작

- 사용자 문서의 캔버스 제목은 실제 파일명의 확장자 제외 부분과 같게 관리한다. 예: `핵심 플레이` ↔ `docs/핵심 플레이.md`.
- 캔버스의 이름 편집을 완료하면 제목 metadata·실제 파일명·앱이 관리하는 참조를 하나의 이름 변경 작업으로 확정한다. 본문 자동 저장마다 파일을 이동하지 않는다. 편집 중의 입력은 초안이며 저장 완료 전의 이름으로 성공 표시하지 않는다.
- 신규 작성·AI 결과 문서·가져오기·복제·프로젝트 간 복사에도 같은 이름 결정 규칙을 적용한다. 파일명이 조정되면 화면 이름도 조정된 결과와 같아야 한다.
- 기존 문서는 현재 표시 제목을 기준으로 파일명을 맞춘다. 프로젝트 열기나 앱 업데이트만으로 일괄 변경하지 않는다. 프로젝트 단위의 `파일 이름 통일`에서 변경 전·후와 충돌·영향 파일을 미리 보여준 뒤 적용한다. 이 일회성 정리 화면은 실제 변경 결과를 검토하기 위한 제품 기능이다.
- 적용 후 카드·검색·목록·속성·파일 위치 표시·탐색기에서 같은 자료를 같은 이름으로 식별한다. 전체 경로·확장자는 속성에서 계속 확인한다.

## 현재 구현에서 확인한 제약

- `DocumentEditingService.save`와 `filesystemDocumentRepository.replace`는 원래 경로의 frontmatter `title`과 본문만 저장한다. 일반 파일 이름 변경 명령은 없다. 기존 단일 파일 저장을 그대로 확장해 참조 파일을 몰래 수정하지 않는다.
- ADR 0003은 제목 편집으로 파일을 이동하지 않는 정책을 명시한다. 이번 계획은 그 정책을 바꾸므로 구현 시 새 ADR과 편집·프로젝트 파일 설계 문서를 함께 갱신한다. 현재 동작과 미래 동작을 구분한다.
- 문서 링크는 안정 ID 기반과 경로 기반이 공존한다. 섹션·출처·HTML 연결·작성 기록·저장 큐·개인 설정도 경로를 보관할 수 있다. 이름만 바꾸는 UI 수정으로 끝낼 수 없다.
- HTML 경로 검증은 `output/index.html`, 버전 파일명, 결과 폴더의 `index.html` 등 제한된 형태를 지원한다. 단순 OS rename 후에는 목록·실행·갱신·삭제 등이 실패할 수 있다. 버전/분류를 유지하면서 이름 있는 HTML 진입 파일을 지원하도록 관리 계약까지 연결한다.
- 기존 v1의 `project.md`와 내부 관리용 문서는 고정 경로를 사용한다. v1 일반 문서의 통일에는 기존 v2 구조 전환을 선행 조건으로 표시하고 기존 서비스·미리보기·복구 경계를 재사용한다. 구조 전환과 이름 변경 결과는 구분해 보고한다.

## 이름 규칙

- 확장자는 유지하고 사용자는 확장자 제외 이름을 편집한다. 한글·공백을 지원하며 앞뒤 공백과 Unicode 정규화를 일관되게 처리한다. 정규화된 최종 이름을 입력 화면에 보여준다.
- 빈 이름, Windows 금지 문자·예약명, 끝의 점·공백, 지원 경로 길이를 검증한다. 사용 불가 문자는 자동으로 제거하여 다른 이름을 만들지 않고 해당 입력을 안내한다. 로컬·서버에서 동일하게 검사한다.
- 충돌은 같은 폴더와 확장자를 기준으로 검사한다. 대소문자·Unicode 정규화 차이를 고려하며 기존 추적 파일과 추적되지 않은 파일을 덮어쓰지 않는다.
- 직접 이름 변경 중 충돌은 입력란에서 해결한다. 생성·복제의 중복 이름에는 `핵심 플레이 (2)` 같은 사용자가 읽을 수 있는 후보를 만들고 실제 파일과 표시 제목에 동일하게 적용한다. 일괄 정리도 제안된 최종 이름을 미리 보여준다.
- 문서 ID·캔버스 위치·종류·상태·작성 기록은 유지한다. 경로에서 ID를 얻던 레거시 문서는 현재 ID를 명시적으로 보존하여 새 경로가 다른 문서로 인식되지 않게 한다.
- 대상은 사용자 Markdown과 HTML 진입 파일이다. 이미지 설명 문서의 `.md` 이름은 같은 규칙을 적용하고 원본 이미지 에셋명은 별도 자산 정보로 유지한다. 내부 AI 작업 명세·히스토리·섹션·HTML 관리 문서의 고정 식별 파일명은 사용자 문서명으로 일괄 변경하지 않는다.

## 구현 순서

### 1. 변경 범위 계산과 공통 계약

- `contracts`에 이름 변경/일괄 통일의 입력·계획·결과 DTO와 공통 명령을 정의한다. 원래 ID·경로·기준 revision·목표 이름·요청 ID를 전달하고 결과에 최종 경로·이름·참조 변경을 반환한다.
- `core`에서 이름 검증·중복 후보·경로 매핑·영향 범위를 계산한다. 계획 조회는 읽기 전용이며 적용 시 최신 파일과 revision을 다시 검사한다.
- `application`은 기존 mutation 큐·프로젝트 세션·권한·잠금·히스토리를 조정한다. UI는 주입된 runtime을 사용하며 filesystem을 직접 호출하지 않는다.

### 2. Markdown 변경·참조·복구

- 현재 문서 저장을 마친 다음 명시적 이름 변경을 수행하고 성공한 경로로 편집기를 재연결한다. 이름 입력 중에는 반복 rename하지 않으며 IME 조합과 기존 본문 저장 큐를 유지한다.
- ID 기반 링크는 그대로 유지한다. 경로 기반 문서 링크와 Markdown 상대 링크·링크 정의·이미지 경로는 기존 파싱/위치 기반 갱신 도구를 재사용한다. 본문에 우연히 등장한 파일명·코드·사용자가 작성한 링크 라벨을 문자열 치환하지 않는다.
- 섹션 멤버, 출처 metadata, HTML 문서 연결, 칸반 등 현재 프로젝트의 경로 참조와 기록 키를 갱신한다. 개명 전후 선택·속성·편집 세션은 같은 문서 ID를 유지한다.
- 영향 파일과 새 경로를 시작 세션에 고정하고 외부 변경·편집 잠금을 검사한다. 실제 여러 파일의 갱신에는 기존 파일 반영 경계와 durable 복구 기록을 연결한다. 대소문자만 바뀌는 이름은 검증된 임시 경로를 거친다.
- 중간 실패/종료 후에는 복구를 완료하거나 재개 가능한 실패 상태를 표시한다. 다른 파일의 외부 변경을 덮어쓰지 않는다. Undo/Redo는 제목·경로·참조를 함께 되돌리며 과거 불변 히스토리 본문은 재작성하지 않는다.

### 3. HTML 실행 파일 연결

- 같은 결과 폴더의 진입 파일을 `전투 화면.html`처럼 변경할 수 있도록 경로 검증·결과 목록/분류/버전·갱신 대상·preview 설정·삭제 대상을 연결한다. 예: `output/prototypes/전투/v001/index.html` → 같은 폴더의 `전투 화면.html`. 분류·버전 폴더는 이름 편집만으로 재편하지 않는다.
- 기존 `index.html`과 레거시 결과 경로를 계속 읽는다. 실행 진입 경로를 결과 descriptor에서 조회하며 임의 HTML 파일을 새 결과로 오인하지 않도록 한다. 결과 ID·버전 정체성을 유지한다.
- iframe·별도 창·웹 게시·AI의 기존 결과 갱신·미리보기 캐시가 새 진입 경로를 사용하도록 연결한다. 파일 확정과 실행 URL 전환을 순서대로 수행하여 기존 실행 화면을 불필요하게 재시작하지 않는다.
- CSS·이미지·스크립트 파일은 보존한다. 앱 관리 참조와 해석 가능한 정적 파일 링크만 갱신한다. 사용자 JavaScript의 동적 경로 등 자동 갱신을 보장할 수 없는 참조가 확인되면 영향 목록에 표시하고 미해결 상태에서 해당 항목의 통일을 완료 처리하지 않는다. HTML `<title>`과 화면 내부 제목은 콘텐츠이므로 임의로 변경하지 않는다.

### 4. UI 연결과 기존 문서 정리

- 이름 입력의 확정·취소·검증·저장 상태를 연결한다. 이름 변경 실패 시 입력과 본문 초안을 보존하고 원래 경로로 편집을 이어갈 수 있어야 한다.
- MD·HTML 카드, 검색·파일 목록, 링크 선택기, 속성·파일 위치 표시를 같은 최종 이름으로 갱신한다. 별도 표시 제목을 남겨 다시 불일치하는 경로를 없앤다.
- 기존 문서 통일 미리보기에서 현재 제목·파일명·최종 이름·충돌·참조 영향·v2 선행 여부를 표시한다. 충돌과 적용 범위가 해결된 계획만 실행하며 적용 직전에 다시 검사한다.
- 한 프로젝트의 승인된 변경 묶음은 하나의 작업으로 추적한다. 구조 전환과 이름 통일은 각자의 확정/복구 상태를 명확히 표시하고 전부가 단일 OS 원자 작업이라고 표시하지 않는다.

### 5. 협업·오프라인·생성 경로 통합

- 로컬과 공동 서버가 같은 이름 규칙과 변경 계획을 사용한다. 서버는 쓰기 권한·revision·영향 파일 잠금·AI 실행/예약 상태를 확인한다. 미지원 서버에서는 제목만 바꾸는 우회 저장을 하지 않는다.
- rename은 서버가 확정하는 온라인 구조 변경으로 처리한다. 오프라인에서는 기존 본문 편집·초안 보존을 유지하고 이름 변경을 저장 완료로 표시하지 않는다.
- 서버에서 이름이 바뀐 뒤 늦게 접속한 클라이언트의 저장 큐·오프라인 초안·선택·개인 설정을 같은 문서 ID와 누적 경로 이력으로 연결한다. 재개명·이전 이름 재사용·반복 요청도 검사한다. 기존 v2 구조 이전표를 그대로 개명표로 사용하면 생기는 다대일/체인/경로 재사용 문제를 먼저 해소한다.
- 신규 작성·가져오기·복제·AI 생성·결과 갱신·다른 프로젝트로 복사의 경로 결정도 통합한다. 사용자가 탐색기에서 직접 파일명을 바꾸는 행위까지 자동 동기화하는 기능은 이번 범위에 포함하지 않는다. 외부 변경은 기존 충돌 감지·재조회로 보호한다.

### 6. 검증과 보고

- 이름 일치·불일치, 한글/공백/긴 이름, 금지 문자·예약명, 중복, 대소문자만 변경, 여러 번 개명, 이전 이름 재사용, 레거시 ID를 검증한다.
- 상대/ID/경로 링크·출처·섹션·이미지·검색, Undo/Redo·히스토리 복원·재시작·외부 변경·중간 실패 복구를 검증한다. 실제 임시 디렉터리를 사용하고 사용자 실자료는 변경하지 않는다.
- 실제 공동 서버와 두 클라이언트로 동시 개명/본문 저장·권한/잠금·끊김/재접속·지연 ACK·미전송 초안·미지원 서버를 검사한다.
- 기본/레거시/분류·버전/가져온 HTML을 포함해 실행·별도 창·파일 위치·정적 리소스·다음 AI 갱신 대상·삭제/복원 경로를 검사한다. HTML 원문과 지원되지 않는 동적 코드까지 자동 교정했다고 주장하지 않는다.
- 타입·contracts/core 타입·린트·아키텍처와 관련 자동 검사를 수행한다. 최종 소스의 Windows 패키지를 한 번 빌드하여 실제 이름 변경·파일/링크·저장·전체 재시작을 확인한다. 이전 UI 작업의 패키지는 소스가 달라지므로 재사용 검증물로 취급하지 않는다.
- 완료 보고에서 구현/검증 범위, 기존 파일 통일 결과와 남은 충돌을 구분한다. 커밋·푸시·배포는 별도 최종 지시까지 수행하지 않는다.

## 완료 기준

사용자가 앱에서 이름을 확정하면 캔버스 제목과 실제 파일명이 일치하고 같은 문서의 본문·링크·위치·기록이 이어진다. 실패·취소·충돌 시 원본과 초안이 보존되며 성공으로 표시하지 않는다. HTML의 이름 변경 후에도 기존 결과를 실행·갱신할 수 있고 공동 프로젝트의 다른 PC에서도 같은 문서로 이어진다.

## 1~2단계 구현 기록 · 2026-11-01

- 계약·공통 계산·이름 변경 서비스·파일 adapter·Electron 조립·UI로 책임을 나눴다. `document-names.ts`의 입력/경로 변경/결과와 `file-name.ts`의 이름 정규화·금지 문자·Windows 예약명·중복 후보를 추가했다. 읽기 전용 `planDocumentName`은 ID·원래 제목/본문과 충돌을 검사하고 실제 영향 파일을 계산한다.
- 새 `renameDocument`는 기존 개인 프로젝트 mutation/session 큐와 로컬 history recorder를 사용한다. AI 실행/잠금·미확정 본문 저장·scope 변경을 거절한다. 현재 공동 reducer 명령으로 노출하지 않으며 공동 프로젝트에서 로컬 사본을 대신 개명하지 않는다.
- 기존 body save 큐와 이름 확정을 구분했다. 제목만 입력 중일 때 파일과 metadata를 개명하지 않는다. Enter·Ctrl+S·편집 완료에서 본문 저장 후 실제 파일명·표시 제목·참조를 함께 갱신한다. 입력란 Escape는 이름 변경을 취소한다. 오류 입력과 초안을 보존하며 정상 이름으로 고쳐 저장하면 이전 오류 표시를 해제한다.
- 기존 Markdown 링크 파서와 metadata 변환을 재사용하여 상대 링크·파일 링크·섹션·출처·작성 기록 키를 연결했다. ID 링크·사용자 링크 라벨·일반 문자열·코드·본문의 원래 H1·알 수 없는 속성·HTML 원문은 보존한다. 경로 기반 문서의 ID는 원래 값으로 고정한다.
- 파일 repository에 개명 journal을 연결했다. 대소문자 개명·오류 복구·다음 열기 복구와 기존 Undo/Redo가 같은 파일 반영 경계를 사용한다. 외부 변경은 덮어쓰지 않고 복구 자료를 남긴다. 완료된 저장 큐의 경로 변경은 새 경로의 ID·base를 검증하며 미전송 요청의 임의 경로 변경은 거절한다.
- 지원 범위는 개인 프로젝트의 docs/ideas 사용자 Markdown이다. 고정 `project.md`는 기존 파일 구조 정리 후 변경해야 하며 내부 AI·HTML 관리 문서는 개명 대상에서 제외한다. 신규 생성·AI·가져오기·복제의 기존 경로 결정은 5단계에서 공통 규칙에 연결한다. 기존 파일의 자동 일괄 개명은 수행하지 않았다.
- 전체 자동 검사 1,065개(실패·skip 0), 일반/계약/core 타입과 린트·서식을 통과했다. 전체 검사에 아키텍처 10개가 포함되며 새 경계 예외는 추가하지 않았다. 기존 Discord mock의 `no-this-alias` 경고 1건은 유지된다.
- 실제 카드 UI에서 개명 후 제목·본문 저장·포커스·드래그·속성·중복 H1·색상 비활성화·패널 회귀를 확인했다. 최종 Windows 패키지의 `document-names-packaged.mjs`는 확정 전 무개명, 실제 파일/링크 변경, 금지·중복 이름의 입력 유지, Escape 취소, 같은 입력란에서 오류 수정, 개명 후 본문 편집, Undo/Redo와 전체 프로세스 재시작을 통과했다. 이전 표시 통일의 `card-appearance-packaged.mjs`도 같은 패키지에서 통과했다. 검사에는 임시 프로젝트·격리 프로필만 사용했다.
- 근거는 `out/document-names-*.log`, `out/document-names-packaged`, `out/card-appearance-packaged`다. 저장 정책 변경은 [ADR 0005](../architecture/decisions/0005-document-file-names.md)에 기록했다. 소스 변경 이후 패키지를 다시 빌드하여 최종 소스로 검사했으며 설치 파일 게시·커밋·푸시·배포는 수행하지 않았다.

## 3~6단계 구현 기록 · 2026-11-01

- HTML 카드 상단에서 실제 진입 파일 이름을 확정한다. 같은 폴더의 `.html` 파일·관리 문서·참조를 갱신하고 고유 ID·버전·폴더·창 위치·게임 원문을 보존한다. 분류 폴더 이동과 레거시 결과 정리도 개명된 진입 파일과 버전을 사용한다. 임의 리소스 HTML은 결과 목록/일괄 정리에서 제외한다.
- ‘더보기 → 설정 및 도구 → 파일 이름 통일…’에서 읽기 전용 검사, 현재 제목·원래 경로·최종 이름·중복 후보·선택 범위·영향 파일을 표시한다. 사용자가 수정한 최종 이름으로 확정하며 최신 파일이 바뀌면 전체 적용을 거절한다. v1의 고정 프로젝트 문서는 기존 구조 정리 UI를 명시적으로 선행한다. 기존 실자료는 자동 개명하지 않았다.
- 공동 프로젝트에 `documentNamesVersion:1`과 3개 공통 명령을 연결했다. 권한·영향 잠금·revision·AI 실행/예약·서버 지원을 검증하고 기존 receipt/SQLite 확정과 mirror 경계를 재사용한다. 오프라인 개명은 거절하며 기존 본문 편집은 보존한다. 재접속한 본문·기존 저장 큐·복구 초안은 ID·이전 경로·base 제목과 파싱된 링크로 최신 이름을 따른다. 새 경계 예외를 추가하지 않았다.
- 직접 작성·가져오기·복제·프로젝트 간 복사·게임 UI 설명은 읽을 수 있는 파일명과 같은 표시 제목을 사용한다. HTML 신규 생성은 버전 폴더 안의 이름 있는 파일을 사용하며, AI Markdown 게시 시 제목을 승인된 실제 출력 파일명과 맞춘다. 실행 뒤 예약 출력 경로를 바꾸지 않는다.
- MD/HTML 대소문자 개명·Undo/Redo·실패 복구에 같은 journal을 사용한다. 일반 과거 본문/HTML 기록은 현재 경로/이름으로 복원하고 명시적 개명은 원래 경로 이동 자체를 되돌린다. HTML 관리 문서만 복원하는 경우도 고유 ID와 현재 이름을 유지한다. 외부 변경과 모호한 옛 경로 재사용은 덮어쓰지 않는다.
- 실제 서버와 두 클라이언트에서 원격 개명 중 미전송 본문 재접속, 동시 개명의 단일 확정, 다른 사용자 잠금·뷰어·구버전 차단, 같은 요청 재전송과 서버 전체 재시작 후 receipt/ID/내용 보존을 검증했다. 실제 임시 Windows 파일에서는 대소문자 개명과 역복원·리소스 보존을 확인했다.
- 최종 소스의 전체 자동 검사 1,079개와 일반/계약/core 타입, 린트·서식을 통과했다. 전체 검사에 아키텍처 검사가 포함된다. 기존 Discord mock의 `no-this-alias` 경고 1건은 유지된다. 마지막 UI 표시 보완 후 관련 79개, HTML 폴더/복원 보완 후 관련 13개도 통과했다.
- 실제 Windows 패키지의 `unified-file-names-packaged.mjs`에서 HTML 검증/취소/정규화 확정·파일/ID/원문/리소스 보존·동일 iframe 유지, 일괄 미리보기·중복 후보·사용자 최종 이름·오래된 미리보기 거절·묶음 Undo/Redo·v1 구조 정리·전체 재시작을 확인했다. 최종 재검증 로그와 화면은 `out/unified-names-*`, `out/unified-file-names-packaged`에 남긴다.
- 정적 HTML URL은 지원 범위에서만 갱신한다. 변경이 필요한 script/style 참조가 발견되면 해당 개명을 거절하고, 임의 동적 JavaScript나 HTML 내부 제목을 자동 수정하지 않는다. OS 탐색기의 직접 개명 자동 추적은 추가하지 않았다.
- 정책과 경계는 ADR 0005 및 편집 명령·프로젝트 파일·협업 세션·회귀 검사 안내에 갱신했다. 커밋·푸시·배포는 사용자 최종 지시까지 보류한다.

최종 확인: 마지막 HTML 폴더·관리 문서 복원 보완 후 같은 소스의 전체 1,079개 검사(실패·skip 0), TypeScript·린트를 통과하고 Windows 패키지를 다시 만들었다. 이 패키지에서 `unified-file-names-packaged.mjs`, `document-names-packaged.mjs`, `card-appearance-packaged.mjs` 세 시나리오가 모두 통과했다. 카드 표시 회귀는 제목 확정 API의 중간 파일 관찰이 아닌 입력란의 실제 저장 완료·편집 종료를 기다린 뒤 정상 종료/재시작을 검사한다. 최종 로그는 `out/unified-names-{all-tests,typecheck,contracts,core,lint,package,native,md-native,cards-native}.log`이며 최종 화면은 `out/unified-file-names-packaged`와 `out/card-appearance-packaged`에 남겼다. 검사 프로젝트/프로필은 정상 종료 후 검증된 임시 경로에서만 정리했다.
